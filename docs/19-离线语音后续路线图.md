## 0. 先把「现在有什么」说准，不夸大

板子上确实在跑一个离线语音固件，但它的实际能力边界比日志看起来要窄：

| 项 | 事实 | 证据 |
|---|---|---|
| 模型加载 | ✅ 通过 | `Successfully load srmodels` / `3 model(s)` / `MultiNet model: mn7_cn` |
| 命令注册 | ✅ 5 条全部 `ESP_OK` | `add [1..5] ... -> ESP_OK` |
| 帧长匹配 | ✅ 512 = 512 | `afe feed=512 nch=1 \| mn chunk=512` |
| **真实说话识别** | ⬜ **还没人试过** | 只注册成功 ≠ 能认出来 |
| 麦克风信号 | 🟡 底噪 38~69 | 安静房间正常，说话时应上到 200+ |
| **控制的「灯」** | ⚠️ **面包板调试 LED** | `main.c:38 PIN_LED = GPIO5` = `config.h` 的 `PIN_LED_COOL`，即 HW-479 的 G 通道 |
| 驱动真实灯具 | ❌ 没有 | 无 MOSFET / 继电器，GPIO 直驱只能点小 LED |
| 断电自启 | ✅ 天然满足 | 固件烧在 flash，上电就跑 |

### 0.1 必须点明的两件事

**第一，GPIO5 不是「灯」，是调试负载。**

`config.h:53` 写的是 `constexpr uint8_t PIN_LED_COOL = 5;`，注释说明面包板上 HW-479 的 G 通道接在 GPIO5。所以现在说「开灯」，亮的是面包板上那颗绿色小灯珠。

而 `docs/11:149` 对 HW-479 的定义是：

> **仅作台架 PWM / 状态输出调试**，不进入产品 BOM，不再开发照明功能

也就是说：**当前版本作为技术验证是合格的，作为产品是零。** 这不影响它的价值——它证明了「ESP32-S3 能离线听懂人话」这件事——但不能拿它当「插电即用的台灯」交付。

**第二，`docs/11` 已经把照明砍掉了。**

产品重定位为「AI 学习机器人」，灯环只是状态反馈，不做照明。这跟你现在要的「开关灯」是两条不同的产品线。所以下一步该往哪走，**取决于你还要不要那个灯**，这是本方案里唯一需要你先回答的问题（见 §4）。

## 1. 第一件事：验证识别，不是继续开发

在写任何新代码之前，必须先确认这 5 条命令真的能被认出来。**这一步你自己做，10 分钟，不需要我。**

```bat
cd /d "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr"
idf.bat -p COM5 monitor
```

然后：**说「你好小智」→ 灯闪 → 6 秒内说「开灯」**。

### 1.1 三种结果，三条分支

| 结果 | 串口表现 | 含义 | 下一步 |
|---|---|---|---|
| **A 全通** | `wake word detected` + `MN id=1 ... LED=ON` | 离线链路成立 | 走 §2 |
| **B 能唤醒、命令不认** | 有 `wake word`，无 `MN id=` | 唤醒词 OK，命令词有问题 | 发音/拼音表，见 §1.2 |
| **C 唤不醒** | 只有 `mic peak=xx` 周期打印 | 麦克风或唤醒词问题 | 看 peak 数值，见 §1.3 |

### 1.2 分支 B：命令不认

先确认你念的是拼音表里那 5 句，一个字都不能差：

```
da kai deng   开灯
guan deng     关灯
liang yi dian 亮一点
an yi dian    暗一点
zui liang     最亮
```

不能说「开个灯」「把灯打开」「打开灯」——MultiNet 是**定词表匹配**，不是语音转文字，多一个字少一个字都不认。

这是它和云端 ASR 最本质的差别：云端 ASR 先转文字再匹配关键词，容错高；MultiNet 直接对声学特征做分类，只认注册过的那几条。**代价是准，收益是不花钱、不联网。**

### 1.3 分支 C：唤不醒

**先看说话时 `mic peak` 的数字**，这一个数就能区分两类问题：

| peak | 判断 | 处理 |
|---|---|---|
| 说话时仍是 10~80 | 麦克风没信号 | 查接线：INMP441 的 L/R 必须接 GND（决定左声道）、SD→GPIO17、BCLK→GPIO16、WS→GPIO18 |
| 说话时到 500~3000 | 麦克风正常，是唤醒词问题 | 「你好小智」念慢一点、清晰一点；房间太吵也会影响 |
| 到 3000 以上 | 可能削顶失真 | 离麦克风远一点 |

**不要一上来就怀疑算法。** 底噪 38~69 说明 I2S 通着，但通着不等于麦克风在拾音——如果 L/R 悬空，读到的就是固定偏移。

## 2. 验证通过后，「插电即用」还差什么

逐项对照，只有两项是真缺口：

| 要求 | 现在 | 缺口 | 成本 |
|---|---|---|---|
| 不需要 PC | ✅ | — | — |
| 不需要 API Key | ✅ | — | — |
| 不需要配网 | ✅ | — | — |
| 不需要配置 | ✅ | — | — |
| 上电自启 | ✅ | — | — |
| **脱离 USB 供电** | ⬜ 现在靠 USB | 换 5V 充电头 | 1 分钟，零成本 |
| **驱动真实灯具** | ❌ 只有调试 LED | MOSFET 或继电器模块 | 需要硬件决策，见 §4 |
| 唤醒词两段式 | 🟡 要先说「你好小智」 | 可关掉门控 | 改一个宏，见 §3 |

**结论：除了「真实灯具」，其余都已经满足了。** 插上充电头，它就是一个不联网、不花钱、不上报数据的离线语音开关。

### 2.1 供电的注意点

ESP32-S3 跑 AFE + MultiNet 时电流峰值约 300~500 mA，加上 INMP441（约 1.4 mA）和 LED，普通 **5V/2A 充电头完全够**。

但有两个坑：

1. **不要用电脑 USB 口长期供电**——枚举过程会拉低电压，且电脑休眠就断电
2. **充电头必须有 5V 输出**，某些快充头在空载时会协商失败，表现为反复重启（日志会出现 `rst:0x3 (RTC_SW_SYS_RST)` 或 brownout）

判断方法：插上充电头后看串口有没有 `ESP-ROM:esp32s3-...` 反复打印。有就是供电问题，不是固件问题。

## 3. 可选优化：去掉唤醒词

改 `main.c:43`：

```c
#define GATE_BY_WAKEUP 1   // 改成 0 = 免唤醒，直接说「开灯」
```

| | `GATE_BY_WAKEUP 1` | `GATE_BY_WAKEUP 0` |
|---|---|---|
| 交互 | 先说「你好小智」，6 秒内说命令 | 直接说命令 |
| 误触发 | 低 | **明显变高**（电视、聊天都可能触发） |
| 功耗 | 低（MultiNet 只在窗口内跑） | 高（一直跑） |
| 适合 | 产品形态 | 自己用、图省事 |

**建议先保持 1。** 误触发的代价不是钱（离线不计费），而是「灯莫名其妙自己亮了」——这个体验问题比多说四个字严重。

真要改，顺手把 `multinet->create(mnName, 6000)` 的 6000 调到 8000，窗口宽一点更好说。

### 4.2 我的判断

**这两条不冲突，但有先后。** 理由：

- 路 1 的软件部分（离线识别）**已经做完了**，剩下的只是驱动电路，1 天能收尾

## 6. 阶段计划

| 阶段 | 做什么 | 验收 | 依赖 | 时间 |
|---|---|---|---|---|
| **M0** | 验证识别（§1） | 说 10 次「开灯」≥8 次成功 | 无 | 10 分钟，你自己 |
| **M1** | 换充电头供电 | 拔掉 USB 仍工作，不重启 | 5V/2A 充电头 | 1 分钟 |
| **M2** | 命令表扩到 8~10 条 | 新增命令同样 ≥8/10 | M0 通过 | 半天 |
| **M3** | 接真实灯具（视 §4 决定） | 说开灯，实际光源亮 | MOSFET 模块 | 1 天 |
| **M4** | DeepSeek 文本链路 | 串口打印出 LLM 回复 | 无（不需要喇叭） | 1 天 |
| **M5** | 喇叭到货后接 TTS | 听到语音回复 | MAX98357 ⬜ | 等硬件 |
| **M6** | 整机合并 / 迁小智 | 语音+屏幕+舵机同时工作 | RIG-Arm ⬜ | 等硬件 |

### 6.1 M2 命令表怎么扩（不给代码，只说规则）

现在 5 条：开灯、关灯、亮一点、暗一点、最亮。

可以加：最暗、亮一半、全亮、调亮、调暗。

**但有两条硬规则**：

1. **音节数要错开。** 「开灯」(3 音节) 和「关灯」(2 音节) 已经够区分了，但别加「开灯吧」「关灯了」这种只差一个字的——MultiNet 会混。
2. **避免同音冲突。** 「最亮」和「最凉」、「暗一点」和「按一点」在声学上接近，实测如果混就把其中一个换掉。

**加到 8~10 条是安全的，超过 15 条要重新测识别率**——词表越大，每条的分辨率越低。这个不是软件限制，是模型特性。

### 6.2 M4 为什么不需要喇叭也能做

DeepSeek 返回的是**文字**。没有喇叭时，把回复 `printf` 到串口，你就能看到它答得对不对。

这验证的是三件事：Key 有效、模型名对、网络通。等 MAX98357 到货，只需要把 `printf` 换成 I2S 播报，前面的链路一行不用改。

**但要说清楚：现在做 M4，得到的是一个「能思考但不会说话」的助手。** 如果这对你没价值，就等喇叭一起做，别拆成两步。
