## 2. 已处理的问题

### 2.1 仓库体积 230 MB → 113 MB

**现象**：代码总量不到 5 MB，`.git` 却有 230 MB。`git count-objects -vH` 显示 **115 MB 松散对象 + 112 MB 打包**，其中 908 个松散对象、1363 个不可达对象。

**定位过程**（这一步最容易走错）：

1. 先按体积排序历史 blob，前五名全是 `server/models/vosk-model-small-cn-0.22/`：压缩包 41.9 MB、`Gr.fst` 24.9 MB、`HCLr.fst` 15.4 MB、`final.mdl` 15.2 MB、`final.ie` 9.5 MB，合计约 107 MB；再加 `docs/design/*.png` 约 20 MB。
2. 这些文件**现在都已被 `.gitignore` 忽略**，但历史里还在。
3. 关键一问：它们挂在哪个引用上？逐个 ref 探测后发现 —— **`origin/main` 根本不可达**（`git rev-list --objects origin/main | grep -c` 返回 0），因此 GitHub API 报告的仓库体积只有 2.3 MB。
4. 真正的持有者是 **`refs/cline/checkpoints/1793328900365_blgql/1`** —— 一个 AI 编程工具在 2026-10-30 10:55 留下的检查点引用。这类引用不在 `refs/heads` / `refs/tags` 里，日常 `git branch -a` 看不见，但 `git gc` 会把它当可达对象保留。

**处理**：先归档 stash 内容（见 2.2），再执行

```bash
git gc --prune=now
```

结果：松散对象清零，不可达对象被回收，`.git` 从 **230 MB 降到 113 MB**。

**剩余 113 MB 的性质**：仍是那 107 MB 的 vosk 模型 + 20 MB 设计稿，被 `refs/cline` 的旧检查点钉住。删掉该引用即可再降到约 5 MB，但那是工具的历史快照（可用于"恢复到某一时刻"），**不是仓库问题，需本人决定**，见第 5 节。

## 4. 维护命令速查

```bash
# 看体积构成（松散对象是否堆积）
git count-objects -vH

# 列出历史最大文件（找"幽灵大文件"）
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1=="blob"{print $3, $4}' | sort -rn | head -10

# 查某个 blob 挂在哪个引用上（含 refs/cline 这类非标准引用）
git for-each-ref --format='%(refname)'

# 回收不可达对象
git gc --prune=now

# 清理已合并且远端已删的分支影子
git fetch --prune origin

# 体检：分支合并状态
git branch -a -vv
```

### 5.1 是否删除 Cline 检查点引用（可再省 108 MB）

`refs/cline` 下有 5 个检查点，最早那个（2026-10-30 10:55）钉住 107 MB 模型 + 部分设计稿。

```bash
# 只删最早那个（别的检查点不动）
git update-ref -d refs/cline/checkpoints/1793328900365_blgql/1
git gc --prune=now      # 预计 .git 113 MB → 约 5 MB

# 或删掉全部检查点
git for-each-ref --format='delete %(refname)' refs/cline | git update-ref --stdin
```

**代价**：Cline 里"恢复到 10-30 那个时刻"的能力会丢失；**不影响**代码、历史、远端。删之前建议先确认近期不用该工具的历史还原。

### 5.2 分支保护是否要真正拦住直推

上一轮推送时 GitHub 回过一句 `3 of 3 required status checks are expected`，但推送**成功了**。说明规则存在，却因为管理员权限（`enforce_admins` 未开）或未勾"Require a pull request"而放行。

如果要严格走 GitHub Flow，需在仓库 Settings → Branches 勾选：

- Require a pull request before merging
- Require status checks to pass before merging（选 CI 的四项）
- Do not allow bypassing the above settings

这只是个开关，属于流程偏好，没有替你改。

### 5.3 `archive/structure-diagram-wip` 标签要不要推到远端

目前只在本地。推上去的好处是换机器也能找回那份中间稿：

```bash

```

不推的话，本地 `.git` 一旦重建（重新 clone），这条标签就没了。
