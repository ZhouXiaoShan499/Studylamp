## 2. 已处理的问题

### 2.1 仓库体积 230 MB → 30 MB

**现象**：代码总量不到 5 MB，`.git` 却有 230 MB。`git count-objects -vH` 显示 **115 MB 松散对象 + 112 MB 打包**，其中 908 个松散对象、1363 个不可达对象。

**定位过程**（这一步最容易走错）：

1. 先按体积排序历史 blob，前五名全是 `server/models/vosk-model-small-cn-0.22/`：压缩包 41.9 MB、`Gr.fst` 24.9 MB、`HCLr.fst` 15.4 MB、`final.mdl` 15.2 MB、`final.ie` 9.5 MB，合计约 107 MB；再加 `docs/design/*.png` 约 20 MB。
2. 这些文件**现在都已被 `.gitignore` 忽略**，但历史里还在。
3. 关键一问：它们挂在哪个引用上？逐个 ref 探测后发现 —— **`origin/main` 根本不可达**（`git rev-list --objects origin/main | grep -c` 返回 0），因此 GitHub API 报告的仓库体积只有 2.3 MB。
4. 真正的持有者是 **`refs/cline/checkpoints/1793328900365_blgql/1`** —— 一个 AI 编程工具在 2026-10-30 10:55 留下的检查点引用。这类引用不在 `refs/heads` / `refs/tags` 里，日常 `git branch -a` 看不见，但 `git gc` 会把它当可达对象保留。

**两轮处理**：

```bash
# 第一轮：归档 stash（见 2.2）后回收不可达对象
git gc --prune=now          # 230 MB → 113 MB

# 第二轮：删除钉住大文件的检查点（见 2.5），再回收
git update-ref -d refs/cline/checkpoints/1793328900365_blgql/1
git gc --prune=now          # 113 MB → 30 MB
```

合计 **230 MB → 30 MB，降 87%**。

剩余 30 MB 里，约 20 MB 是 `docs/design/` 的设计稿，挂在 `archive/structure-diagram-wip` 标签上（该标签要保住 11-02 的 WIP 及其基线的完整血缘）。这部分是主动选择保留的，不是残留垃圾。

### 2.5 删除钉住 127 MB 的 AI 工具检查点

`refs/cline` 下有 5 个检查点，最早那个（2026-10-30 10:55）把 107 MB 的 vosk 模型和 20 MB 设计稿钉在可达范围内。删它会失去"恢复到 10-30 那个时刻"的能力，因此删除前做了三步核验。

**第一步：确认它自己没存独有文件**

```bash
git ls-tree -r --name-only refs/cline/checkpoints/1793328900365_blgql/1 | sort > /tmp/cp.txt
git ls-tree -r --name-only main | sort > /tmp/main.txt
comm -23 /tmp/cp.txt /tmp/main.txt      # 输出为空 → 当前树里没有 main 之外的文件
```

**第二步：确认历史祖先里也没有独有源码**。这一步才是关键 —— 检查点自己的树是干净的，但它的祖先提交里可能藏着别处没有的工作。把"仅该引用可达、main 不包含"的全部路径列出来：

```bash
git rev-list --objects <ref> --not main | awk 'NF>1{$1=""; sub(/^ /,""); print}' | sort -u > /tmp/uniq.txt
comm -23 /tmp/uniq.txt /tmp/main.txt
```

结果 28 条，全部是 `server/models/vosk-model-small-cn-0.22/**`（第三方模型，可从 alphacephei 重新下载）、`server/test_zh.wav`（测试音频，`*.wav` 本来就被忽略）、`firmware/idf/pdm_probe/sdkconfig`（ESP-IDF 生成物，同样被忽略）。**没有一行源码。**

**第三步：确认 8 个独有提交里的真实工作已在 main 中**

```bash
git cherry main <ref>
```

只输出 2 个 `+`（`08b307e` / `ffe748a`，都是"untracked files / index on cline checkpoint"这类快照提交）；5 个带正常提交信息的历史提交全部是 `-`，说明补丁在 main 里已有等价提交。逐个按标题核对，对应关系如下：

| `2223246` feat(firmware): 台架硬编码可配，接入离线命令词串口 | `c19b95e`（PR #19） |

另外，删 git 对象**不会动工作区**：`server/models/`（108 MB）和 `server/test_zh.wav` 都还在磁盘上，只是不再被 git 记录。

**执行**：

## 4. 维护命令速查

```bash
# 看体积构成（松散对象是否堆积）
git count-objects -vH

# 列出历史最大文件（找"幽灵大文件"）
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1=="blob"{print $3, $4}' | sort -rn | head -10

# 找出是谁钉住了某个大 blob（关键：必须遍历所有 ref，含 refs/cline 这类非标准引用）
BLOB=<blob sha>
for r in $(git for-each-ref --format='%(refname)'); do
  git rev-list --objects "$r" 2>/dev/null | grep -q "^$BLOB" && echo "  $r"
done

# 列出所有引用类别（heads/tags/remotes 之外还有什么）
git for-each-ref --format='%(refname)' | sed 's|refs/\([^/]*\)/.*|refs/\1|' | sort | uniq -c

# 回收不可达对象
git gc --prune=now

# 清理已合并且远端已删的分支影子
git fetch --prune origin

# 体检：分支合并状态
git branch -a -vv
```
