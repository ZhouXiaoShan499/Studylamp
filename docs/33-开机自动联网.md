# 33 开机自动联网（2026-11-16）

> **文档性质**：把「必须打开网页点『连接设备』」改成「插上电自己连」的实施记录。
>
> **一句话**：设备记住最多 5 张 WiFi，开机先试上次那张；不在眼前就扫一遍空口，按信号强弱把看得见的已保存网络依次试过去。配过一次之后，插电就进语音链路，页面只是可选的遥控器。

---

## 0. 问题在哪

原来的联网路径是「单条凭据 + 人肉触发」：

| 现象 | 根因 |
|------|------|
| 换到另一个地方（家里 ↔ 办公室）就不联网 | NVS 只存一组 `ssid`/`pass` |
| 必须打开网页点「连接 WiFi / 连接设备」 | 凭据只在人点按钮时才写；`live.html` 还得先连 USB |
| 密码错、路由器换了，只能看到 `wifi=down` | 重试永远只试同一张，没有「换一张」的概念 |
| 热点兜底要等网页里的人发现设备掉线 | 设备自己没有「挑网」的能力，只能等指令 |

语音识别本来就跑在板内（INMP441 → 腾讯云 ASR → LLM），USB 只承担「看结果」。
所以真正卡住「插电即用」的不是音频，而是**设备不会自己选网**。

## 1. 目标行为（对齐笔记本）

```text
上电
 │
 ├─ 有保存的网络？
 │    ├─ 没有 → 开热点 LAMP-1-XXXX（一次性配网入口）
 │    └─ 有   → 先试「上次连上的那张」────────────── 1~3 s 通常完成
 │                 │失败
 │                 ▼
 │            扫一遍 2.4 GHz 空口
 │                 │
 │                 ├─ 看得见的已保存网络：按 RSSI 从强到弱依次试（每张 12 s 上限）
 │                 ├─ 一张都看不见：盲试上次那张（隐藏 SSID 只能这么连）
 │                 └─ 全失败：30 s 后重来；同时热点兜底，手机可介入
 │
 └─ 连上 → 记下 SSID 作为下次快路径 → SNTP 对时 → 语音链路可用
```

关键取舍：

- **不做「连上之后还主动切到更强的那张」**。笔记本会这么干，但灯是长期在线的设备，
  中途换网会让正在上传的录音失败、网页地址也变了。只有掉线才重新选。
- **扫描是异步的**，不阻塞 `loop()`；只有用户在页面上点「刷新」时才同步等 2~6 秒。
- **每张网络 12 秒上限**，密码错/SSID 不在空口时会提前判失败（3 s / 6 s），
  避免五张网络串行等满一分钟。

## 2. 数据模型

NVS 命名空间仍是 `lampwifi`：

| 键 | 内容 | 说明 |
|----|------|------|
| `nets` | `[{"s":"ssid","p":"pass"}, ...]` | 最多 `kMaxNetworks = 5` 张，顺序不重要 |
| `last` | 上次成功连上的 SSID | 开机快路径 |
| `ssid` / `pass` | 同上一条网络的明文 | **兼容键**：老固件只认这两个，回刷后不用重新配网 |

迁移规则：

1. `nets` 存在 → 直接读；坏 JSON 只打一行日志，不阻止开机。
2. `nets` 不存在、`ssid` 有值 → 迁移成一张表并立刻写回 `nets`。
3. 都没有 → 用 `secrets.h` 的 `LAMP_WIFI_SSID`/`LAMP_WIFI_PASS` 播种（开发板兜底）。
4. 每次连接成功才更新 `last`，且只有 SSID 变了才写 flash。

密码只写一次；`saveNets()` 只在增删改网络时调用，重试过程不碰 NVS。

## 3. 固件

新增 `firmware/include/wifi_link.h` + `firmware/src/wifi_link.cpp`，把原来散在
`main.cpp` 里的 250 行 WiFi 逻辑收成一个状态机：

```text
Idle ──有凭据/start()──► Connecting(快路径) ──成功──► Online
                              │失败                    │掉线 4 s
                              ▼                        ▼
                          Scanning ──有候选──► Connecting(第 n 张)
                              │没有/全失败                │
                              ▼                          │
                          Backoff(30 s) ◄────────────────┘
```

对外接口（`wifilink::`）：

| 函数 | 用途 |
|------|------|
| `begin()` / `start()` / `tick(now)` | 读表 → 外设就绪后开射频 → 推进状态机 |
| `connect(ssid, pass)` | 保存并立即连；表满时替换最久没用的那张 |
| `connectSaved(n)` | 用存好的密码连第 n 张（`wifi use` / 网页点击） |
| `forget(ssid)` / `clearAll()` / `autoConnectNow()` | 增删与手动重选 |
| `scan(timeoutMs)` + `scanSsid/Rssi/Channel/Secure/KnownIndex` | 同步扫描，给网页和串口共用 |
| `online()` / `activeSsid()` / `ip()` / `rssi()` / `phase()` / `busy()` / `summary()` | 状态查询 |

`main.cpp` 只剩两件事：

- `wifiUrlDecode()`：网页参数解码（保持原约定，`+` 不当空格）；
- `wifiHousekeeping()`：连上后每 5 秒把系统时钟灌给 `timers`（TC3 签名要 ±5 分钟）。

`net_console::begin(bool)` 的参数保留但不再当静态快照用——一律查 `wifilink`，
否则「热点页面里刚配完网」会被旧快照判成「从未配网」，又把热点开起来。

### 3.1 和热点兜底的配合

`net_console` 在 25 秒还没 IP 时开热点，但加了一个条件：

```cpp
const bool canBreakIn = !wifilink::busy() || sinceBoot >= kApFallbackMs + 35000;
```

`busy()` = 正在连接或扫描。`WiFi.mode(WIFI_AP_STA)` 会把射频重配一遍，正好打断
正在进行的那次连接；所以连接/扫描期间不插队，最多等到 60 秒硬上限。

热点开着时，`wifilink` 的断开一律走 `WiFi.disconnect(!netconsole::apActive())`：
热点在跑时只断 STA，不关射频，否则手机上的配网页面会瞬间掉线。

## 4. 命令与 HTTP 接口

### 4.1 串口（网页命令走同一个分发器）

```text
wifi                        已保存的网络 + 当前状态
wifi scan                   列出附近 AP（序号 / RSSI / 信道 / 加密 / 是否已保存）
wifi join <n>               连扫描结果第 n 个（用已保存密码）
wifi use <n>                连已保存列表第 n 个
wifi connect <ssid> [pass]  新增/更新并立即连（'-' = 开放网络）
wifi forget <n|ssid>        删一张
wifi auto                   立刻重新选网
wifi clear                  清空（有 secrets.h 时回落）
```

### 4.2 设备页接口

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/wifi/scan` | 同步扫一次，返回 `[{ssid,rssi,ch,secure,saved}]`，最多 24 个 |
| GET | `/api/wifi/networks` | 已保存的表 + 在线状态 + 哪张是 `last`/`active` |
| POST | `/api/wifi/connect` | `{"ssid":"x","pass":"y"}`；只有 `ssid` 时用存好的密码 |
| POST | `/api/wifi/forget` | `{"ssid":"x"}` |

`/api/state` 的 `net` 增加三个字段：`phase`（idle/connecting/scanning/online/retry）、
`saved`（张数）、`last`（上次 SSID）。页面靠 `phase` 区分「正在连」和「真没网」。

`connect` 只负责「保存 + 开始连」，不等结果：12 秒的连接过程会把 HTTP 拖到超时。
页面 1.5 s / 6.5 s 各刷新一次状态。

### 4.3 页面

`web/device.html` 的「WiFi 设置」从「两个输入框」改成「两张列表」：

| 区块 | 交互 |
|------|------|
| 附近的网络 | 展开面板自动扫描；点未保存的加密网络 → 就地弹密码行；点已保存的 → 直接连；开放网络 → 直接连 |
| 已保存 | 显示「在用 / 上次连的 / 备用」，可单独「忘记」 |
| 手动添加 | 折叠在最后，只给隐藏 SSID 用；「全部清除」也在这里 |

信号强弱用四根竖条表示（≥-55 / ≥-65 / ≥-75 / 其余），和手机 WiFi 列表的读法一致。

## 7. 边界

| 项 | 现状 | 说明 |
|----|------|------|
| 频段 | 只认 2.4 GHz | ESP32-S3 没有 5 GHz；同一 SSID 的 5 GHz 热点扫不到 |
| 连上后不切网 | 保持当前 | 避免换网打断录音；掉线才重选 |
| 密码 | NVS 明文 | 能物理接触设备即可读；与旧实现一致 |
| 热点密码 | 固定 `lamp12345` | 产品化应每台独立 |
| 隐藏 SSID | 手动添加 | 扫描列表不显示空名 AP |
| 扫描代价 | 2~6 s 射频占用 | 只在用户点「刷新」时发生；自动选网用异步扫描 |
| 同 SSID 多 AP | 取最强那个 | 不做 BSSID 绑定，漫游交给驱动 |
| 热点与 STA 并存 | 连上后热点不关 | 保持「配网页不断线」，也方便现场排障 |

## 8. 下一步

1. **按键重置**：长按「学习」+「模式」5 秒清空 `nets` 并开热点，替代「必须能打开网页才能 clear」。
2. **配网码**：热点密码改成机身贴纸上的随机码，顺便解决「谁都能连」。
3. **RSSI 历史**：连续三次低于 -80 dBm 才考虑换网，比「一掉线就重选」更稳。
4. **扫码配网**：热点页生成二维码，手机扫码直接打开 `http://192.168.4.1/`，省掉手输地址。
