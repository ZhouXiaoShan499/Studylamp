# 40 第二阶段连接路线与 P0 实施

> **文档性质**：第二阶段启动方案。先给连接路线，再给 P0 验证步骤；P0 通过后才写业务固件。
>
> **代码边界**：P0 用官方示例，**不改现有灯固件**；P1 以后新增 `firmware/idf/lamp_av`。本次不动代码。
>
> **关联**：[38 第二阶段技术细化](38-摄像头语音一体化改造方案.md)、[39 两阶段总览](39-第一阶段与第二阶段实施计划.md)。

---

## 0. 结论

- 第二阶段 = **摄像头 + 咪头 + 喇叭都上灯**，去掉 INMP441，ESP32-S3 当 **USB Host**。
- **先做 P0**：用官方 `usb_camera_mic_spk` 示例验证 4 件事——枚举、UVC 出图、UAC 录音、UAC 放音。
- 连接路线：**CAM12 → USB-A → USB-C OTG → 板载 USB 口**；板子供电/日志走 **COM 口**；5V/2A；INMP441 移除。
- 不要用 3V3 给摄像头；不要把电脑插到 USB 口。

---

## 1. 连接路线

```text
                5V/2A
                  │
        ┌─────────┴─────────┐
        │   COM 口（UART）  │──USB──> PC（烧录/日志）
        │   ESP32-S3        │
        │   USB 口（native）│
        └─────────┬─────────┘
                  │ USB-C OTG
                  │
            USB-A 母座/公头
                  │  红5V  绿GND  黄D−  黑D+
             ┌────┴────┐
             │ CAM12   │
             │  MIC白座 │── 咪头
             │  SPK白座 │── 喇叭
             └─────────┘

GPIO4 ← HW-483（+3V3 / −GND）
GPIO5 → HW-479 G（−GND）
INMP441：移除
```

### 1.1 线序

| CAM12 | USB-A | 说明 |
|---|---|---|
| 红 | 1 脚 VBUS | **5V，不是 3V3** |
| 绿 | 4 脚 GND | |
| 黄 | 2 脚 D− | |
| 黑 | 3 脚 D+ | |

> 颜色不可信，按模块丝印/说明书；用万用表通断档确认到 USB-A 的 1/2/3/4 脚。

### 1.2 连接表

| 端点 | 接到 | 说明 |
|---|---|---|
| CAM12 4 线 | USB-A 母座/公头 | 红/绿/黄/黑 |
| USB-A | **USB-C OTG → 板载 USB 口** | ESP32-S3 当 Host |
| 板子供电/日志 | **COM 口（UART Type-C）5V/2A** | 烧录/日志走这里 |
| CAM12 咪头/喇叭 | 模块 MIC / SPK 白座 | UAC |
| INMP441 | **移除** | 3V3 只给按键/RGB |
| HW-483 | +3V3 / −GND / GPIO4 | 不动 |
| HW-479 | −GND / GPIO5 | R/B 悬空 |

> 也可以不经过 USB-A，直接把 4 根线接到 GPIO19/20/5V/GND，见 §1.3。

### 1.3 直接接 GPIO19/20（可选，你现在的做法）

| CAM12 | 接到 |
|---|---|
| 黄 D− | **GPIO19** |
| 黑 D+ | **GPIO20** |
| 红 5V | 5V 排针（或外部 5V） |
| 绿 GND | GND |

可以，等价于走 USB-C 口；但要注意：

- **不要同时把电脑插到 USB-C 口**：PC 的 D+/D− 和摄像头并在同一对线上，会抢总线；用 **COM 口**供电/烧录/日志。
- 板载 USB-C 座子的 D+/D− 仍并在 GPIO19/20 上，相当于一段短线；Full-Speed 一般能容忍，不稳就改走 USB-C OTG。
- D+/D− 尽量短、双绞、带 GND 回线；长杜邦线容易枚举失败。
- 枚举失败先对调黄/黑（D−/D+ 标反很常见）。
- 长期用建议加 USB TVS（如 USBLC6-2SC6）；面包板阶段可先不加。
- 摄像头 5V 不要接 3V3；5V 不要上面包板 + 轨。

## 2. 端口识别（很容易插错）

YD-ESP32-S3 有两个 Type-C：

| 口 | 丝印 | 用途 | 第二阶段怎么用 |
|---|---|---|---|
| **USB** | `USB` | 原生 USB（GPIO19/20），当前是 COM6 | **接摄像头**（Host） |
| **COM** | `COM` / `UART` | USB-UART 桥（CH343/CP2102） | **供电 + 烧录 + 日志** |

- 现在电脑看到的 COM6（VID:PID=303A:1001）是原生 USB 口；进入 Host 模式后它会消失，这是正常的。
- 烧录/看日志要用 **COM 口**对应的 COMx（设备管理器里另一个串口）。
- 如果板子背面有 **USB-OTG 焊点/跳线**，按原理图确认是否需要短接。

## 3. 供电

| 项 | 做法 |
|---|---|
| 板子 | COM 口接 **5V/2A** 充电头（或 PC USB，但 PC 口只有 500mA） |
| 摄像头 | 5V 从 **5V 排针**取，或量 USB 口 VBUS 有 5V 就从 VBUS 取；二选一，不要双供 |
| 去耦 | 摄像头 5V/GND 并 **470µF + 100nF** |
| 地 | 摄像头 GND 与板子 GND 共地（USB 线已共地） |

> 板载 USB 口不一定对外输出 5V。先量 USB 口 VBUS 对 GND；没有 5V 就从 5V 排针飞线，D−/D+ 仍接 USB 口。

## 4. P0 要验证的 4 件事

| # | 验证 | 期望 | 失败先查 |
|---|---|---|---|
| 1 | USB 枚举 | 日志出现摄像头 VID/PID、UVC/UAC 接口 | VBUS、D+/D− 是否反、OTG 转接、USB-OTG 跳线 |
| 2 | UVC 出图 | MJPEG 帧，480×320 或 800×480 | 摄像头是否支持 UVC 1.1/1.5 + MJPEG + Full-Speed |
| 3 | UAC 录音 | 说话时麦克风 PCM 有 RMS 变化 | 摄像头是否暴露 UAC 输入；咪头是否插好 |
| 4 | UAC 放音 | 测试音/提示音能听到 | 摄像头是否暴露 UAC 输出；喇叭是否插好 |

**四项全过才进 P1。** 任何一项不过，先停，按第 7 节回退。

## 5. P0 工程怎么来

用乐鑫官方 `esp-iot-solution` 的 `usb_camera_mic_spk` 示例，**不要动 `firmware/` 里的灯固件**。

```powershell
# 1. 取示例（release/v2.0 与 IDF 5.4.3 配套）
git clone --depth 1 -b release/v2.0 https://github.com/espressif/esp-iot-solution.git D:\esp-iot-solution

# 2. 进示例目录
cd D:\esp-iot-solution\examples\usb\host\usb_camera_mic_spk

# 3. 用仓库里的 IDF 包装脚本（路径按你机器）
& "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr\idf.bat" set-target esp32s3

# 4. 配置
& "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr\idf.bat" menuconfig

# 5. 烧录 + 监视（COMx = COM 口，不是原来的 COM6）
& "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr\idf.bat" -p COMx flash monitor
```

### 5.1 配置项（menuconfig + 示例宏）

| 项 | 值 | 位置 | 原因 |
|---|---|---|---|
| PSRAM | 开启；Octal | menuconfig | N16R8 是 octal PSRAM；UVC 帧缓冲要用 |
| Console | **UART0**（不是 USB-Serial-JTAG） | menuconfig | 日志走 COM 口 |
| `ENABLE_UVC_CAMERA_FUNCTION` | 1 | 示例 `main.c` 顶部宏 | 开摄像头 |
| `ENABLE_UAC_MIC_SPK_FUNCTION` | 1 | 示例 `main.c` 顶部宏 | 开咪头+喇叭 |
| `ENABLE_UVC_FRAME_RESOLUTION_ANY` | 0，固定 480×320 | 示例 `main.c` 顶部宏 | 先求稳 |
| `ENABLE_UVC_WIFI_XFER` | 0 | 示例 `main.c` 顶部宏 | P0 先看串口；通过后再开 WiFi 图传 |
| `ENABLE_UAC_MIC_SPK_LOOPBACK` | 1（短时） | 示例 `main.c` 顶部宏 | 验证咪头→喇叭；音量小，防啸叫 |
| VBUS GPIO | -1（外部 5V） | 示例配置/宏 | 开发板没有 VBUS 开关时用外部供电 |

> 这些 `ENABLE_*` 宏在示例的 `main.c` 顶部，不在 menuconfig；改的是**示例工程**，不是灯固件。
>
> 如果编译报 `override_path` 相关错误：按示例 README/CSDN 记录，删掉 `main/idf_component.yml` 里的 `override_path`，让它用已安装的 `usb_stream` 组件。

## 6. P0 日志与判定

### 6.1 期望日志

- USB Host：设备连接、VID/PID、配置描述符。
- UVC：接口/格式（MJPEG）、分辨率、帧回调。
- UAC：麦克风帧、扬声器端点。
- 示例自己的 `frame callback` / `mic callback` 打印。

### 6.2 判定表

| 结果 | 判定 | 下一步 |
|---|---|---|
| 四项全过 | ✅ P0 通过 | 进 P1 |
| 枚举失败 | ❌ 硬件/线序 | 量 VBUS、换 D+/D−、换 OTG、查跳线 |
| 枚举成功但 UVC 失败 | ❌ 摄像头不兼容 | 查是否 HS-only/非 MJPEG；换 2MP FS 摄像头 |
| UVC 成功但 UAC 失败 | ⚠️ 无 UAC | 保留 INMP441，或换带 UAC 的摄像头 |
| UAC 放音失败 | ⚠️ 输出端点/喇叭 | 查喇叭插座、UAC 输出描述符 |

## 7. P0 失败的回退

1. **保留 INMP441**，摄像头接电脑（电脑当 Host），先做过渡验证；
2. 或第二块 ESP32-S3 当 A/V 协处理器；
3. 或换 **2MP Full-Speed MJPEG** 摄像头再试。

不要为了“必须用 CAM12”硬改业务固件；P0 就是用来止损的。

## 附录 A：P0 实测记录（2026-11-18）

### A.1 构建

- 基线：`esp-iot-solution` `release/v2.0`，`usb_stream` **1.4.0**，ESP-IDF **5.4.3**。
- **1.4.0 与 IDF 5.4.3 不兼容**，P0 构建时做了 4 处临时补丁（只改 `esp-iot-solution` 克隆，不改灯固件）：
  1. 删除 `fifo_bias` 相关 6 处——IDF 5.4.3 的 `hcd_port_config_t` 没有该字段。
  2. `sdkconfig`：`CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`、`CONFIG_USJ_ENABLE_USB_SERIAL_JTAG=n`——否则 USB-Serial-JTAG 占着 PHY，`hcd_install` 失败。
  3. `hcd_config_t` 增加 `.peripheral_map = 1 << USB_PORT_NUM`——IDF 5.4.3 必需，否则 `ESP_ERR_INVALID_ARG (0x102)`。
  4. `USB_PORT_NUM` 由 `1` 改为 `0`——ESP32-S3 只有 1 个 OTG 口（`SOC_USB_OTG_PERIPH_NUM=1`），端口号 1 越界。
- 配置：16 MB flash、Octal PSRAM、Console UART0 @115200。
- 产物：`D:\esp-iot-solution\examples\usb\host\usb_camera_mic_spk\build\usb_camera_mic_spk.bin`（约 424 KB）。

### A.2 烧录

- 板子 COM 口为 **COM5**（CH343），已成功烧录。
- 原生 USB 口（COM6）在 Host 模式下不再出现，属正常。
- 启动日志（关键行）：

```text
I (1440) USB_STREAM: UVC Streaming Config Succeed, Version: 1.4.0
I (1451) USB_STREAM: UAC Streaming Config Succeed, Version: 1.4.0
I (1468) USB_STREAM: USB stream task start
I (1498) USB_STREAM: USB Streaming Start Succeed
I (1498) USB_STREAM: Waiting USB Device Connection
```

- HCD 已安装成功，USB Host 已启动；现在等摄像头枚举。

### A.3 当前状态与下一步

- 当前：`Waiting USB Device Connection`，摄像头尚未枚举。
- 待查：摄像头 5V / GND 是否接好；黄 D− 是否接 GPIO19、黑 D+ 是否接 GPIO20；D+/D− 是否接反；USB-C 口是否还插着电脑；板子是否有 USB-OTG 跳线未处理。
- 期望枚举日志：`HCD_PORT_EVENT_CONNECTION` → `USB Speed: full-speed` → 设备/配置描述符 → `UVC ...` / `UAC ...` → `frame callback` / `mic peak=...`。
- 注意：P0 已覆盖灯固件；要恢复灯功能，重烧 `lamp_s3_tencent` 即可。

### A.4 引脚电平实测（2026-11-18 17:05）

P0 在启动 USB Host 之前，先把 GPIO19/20 当普通输入读一次（内部下拉）：

```text
I (1477) uvc_mic_spk_demo: USB pins idle: GPIO19(D-)=0 GPIO20(D+)=0
I (1529) USB_STREAM: USB Streaming Start Succeed
I (1529) USB_STREAM: Waiting USB Device Connection
```

判读：

| GPIO19(D−) | GPIO20(D+) | 含义 |
|---|---|---|
| 0 | 0 | **摄像头没供电 / 没接上 / 地不共**（本次实测） |
| 0 | 1 | 正常：摄像头 D+ 上拉已出现，可以枚举 |
| 1 | 0 | 黄/黑接反（D−/D+ 反） |
| 1 | 1 | 两线都被拉高：查短路、或 USB-C 口是否还插着电脑 |

供电正常的 USB 设备会把 D+ 上拉；两边都是 0，说明摄像头侧没有“设备存在”的电信号。下一步先量：

1. 摄像头 **红−绿 = 5V**；板子 **5V 排针−GND = 5V**；
2. **黄 ↔ GPIO19**、**黑 ↔ GPIO20** 通断；
3. 摄像头 4 线插头是否插紧、GND 是否共地；
4. USB-C 口是否还插着电脑（必须拔掉）。

> P0 现在开机后有 **10 秒窗口**，每秒打印一次 `USB pins idle n/10`；可以在这 10 秒内接线/上电，观察 GPIO20 是否从 0 变 1。10 秒后 USB Host 启动，之后再插入设备也会走热插拔。
>
> 如果板子只通过 COM5 供电，**5V 排针可能没有 5V**；先量 5V 排针对 GND。没有 5V 就用 5V/2A 从 5V 排针供电（COM5 只做日志），或给摄像头独立 5V（共地）。
>
> **USB CDC / JTAG on boot 在 P0 里是关的**：P0 是 ESP-IDF 工程，`CONFIG_ESP_CONSOLE_UART_DEFAULT=y`、`CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`、`CONFIG_USJ_ENABLE_USB_SERIAL_JTAG=n`，日志走 UART0（COM5），19/20 让给 USB Host。HCD 能启动就是证据。Arduino 灯固件 `lamp_s3_tencent` 的 `ARDUINO_USB_CDC_ON_BOOT=1` 是开的，但那是另一套固件，现在没跑。

### A.5 按键 / 灯测试（P0 临时任务）

P0 是摄像头固件，本来没有按键/灯代码；为了确认硬件，在 P0 里加了一个临时任务：

- GPIO4 = HW-483 按键（内部上拉，低有效）；
- GPIO5 = HW-479 G 灯；
- 每按一次翻转一次，串口打印。

实测日志：

```text
I (1488) uvc_mic_spk_demo: button/LED test ready (GPIO4 button, GPIO5 LED)
I (6555) uvc_mic_spk_demo: button pressed -> LED ON
I (7575) uvc_mic_spk_demo: button pressed -> LED OFF
```

结论：**按键和 HW-479 G 都是好的**；“按下没反应”是因为 P0 固件没有灯的业务逻辑，不是硬件坏。

> 这个测试只做“按一下翻转”，不是灯固件的“短按开关 / 长按最亮 / 网页控制”。要恢复原来的灯语义，重烧 `lamp_s3_tencent`。

### A.6 按键/LED、摄像头、灯语义能否互通？

先分清三样东西：

| 代号 | 内容 | 现在在哪 |
|---|---|---|
| ① | 按键 GPIO4 + LED GPIO5（硬件通路） | P0 临时测试 / 灯固件 |
| ② | 摄像头 USB Host（UVC + UAC） | P0 |
| ③ | 灯的业务语义（短按/长按、WiFi 网页、云语音） | `lamp_s3_tencent`（灯固件） |

组合矩阵：

| 组合 | 现在能互通吗 | 说明 |
|---|---|---|
| ① + ② | ✅ **P0 已经同时包含** | P0 有临时按键任务 + USB Host；摄像头硬件还没接好 |
| ① + ③ | ✅ 灯固件 | `lamp_s3_tencent` 有按键/LED/网页/语音，但没有摄像头 |
| ② + ③ | ❌ **没有这版固件** | 需要把 P0 的 USB Host 合并进灯业务 |
| ① + ② + ③ | ❌ | 需要 `lamp_av`（单机合并版） |

**结论：硬件可以互通，固件现在不行。** P0 和灯固件是两张互斥的镜像，一块板一次只能跑一个；P0 已经把①和②放在一起了，缺的是③。

## 合并路线

### 方案 A：单机 `lamp_av`（推荐，3–4 周）

一个 ESP-IDF 5.4.3 工程，同时包含：

- P0 的 `usb_host` + `usb_stream`（UVC + UAC，含本次 4 处 IDF 5.4.3 补丁）；
- GPIO4 按键 / GPIO5 LED / 灯状态；
- WiFi + 网页控制台；
- 云 ASR / LLM / TTS；
- INMP441 移除，UAC 咪头/喇叭。

合并顺序：

1. P0 摄像头枚举通过（先修硬件）；
2. 按键/LED（P0 已有测试任务）；
3. WiFi + 网页；
4. 云 ASR/LLM/TTS；
5. 灯语义（短按/长按/预设）；
6. 联调/稳定性。

**资源判断**：GPIO4/5 与 USB 19/20 不冲突；WiFi 与 USB Host 可共存；主要风险是内存/CPU、回声/AEC、UVC 带宽。

### 方案 B：双板/双 MCU（1–2 天）

- 灯板继续跑 `lamp_s3_tencent`（①+③）；
- 第二块 ESP32-S3 或 PC 跑 P0（②）；
- 通过 UART/WiFi 把摄像头/语音结果送给灯。

不是单机，但最快让三样同时工作。

### 方案 C：换着烧（不叫互通）

- 测摄像头烧 P0（①+②）；
- 演示灯烧 `lamp_s3_tencent`（①+③）；
- 一次只有一个，不能同时。

### 建议

1. **先修摄像头枚举**：目标 `GPIO19(D-)=0 GPIO20(D+)=1`；现在还是 `0/0`。
2. 摄像头通过后，走 **方案 A** 做单机 `lamp_av`；如果只想先演示，走 B。
3. 不要为了“同时有”去反复换烧；换烧只能验证，不是产品形态。

### A.7 WiFi + 网页（P0 快速验证）

把示例的 `ENABLE_UVC_WIFI_XFER` 改为 `1` 后，P0 自带 WiFi AP + 网页：

```text
camera wifi: wifi_init_softap finished.SSID:ESP32S3-UVC password:
wifi:mode : softAP (d0:cf:13:01:2d:dd)
camera_httpd: Starting web server on port: '80'
esp_netif_lwip: DHCP server started ... IP: 192.168.4.1
camera_httpd: Starting stream server on port: '81'
```

- SSID：`ESP32S3-UVC`，**无密码**；
- 网页：`http://192.168.4.1/`；视频流端口 81；
- 页面打开后要**手动点 `Start Stream`**；流地址是 `http://<IP>:81/stream`，不点不会出图；
- 摄像头仍 `0/0` 时，**页面能开、没有画面**；点 Start Stream 后，`:81/stream` 会一直等待/超时；
- WiFi + HTTP 让 app 超过默认 1MB 分区，已改成 `SINGLE_APP_LARGE`（1.5MB）。

> 这是 **AP 模式**，不是连家里路由的 STA，也没有云语音；要“家里 WiFi + 云语音”，走 `lamp_av` M1/M3。

### A.8 连上家里 WiFi（STA + AP）

从 `firmware/include/secrets.h` 读 SSID/密码，写入 P0 的 `CONFIG_ESP_WIFI_SSID` / `CONFIG_ESP_WIFI_PASSWORD`（不打印值）：

```text
camera wifi: connect to ap SSID:Xiaomi_037C password:***
wifi:mode : sta (d0:cf:13:01:2d:dc) + softAP (d0:cf:13:01:2d:dd)
camera_httpd: Starting web server on port: '80'
esp_netif_lwip: DHCP server started ... IP: 192.168.4.1
camera_httpd: Starting stream server on port: '81'
esp_netif_handlers: sta ip: 192.168.31.91, mask: 255.255.255.0, gw: 192.168.31.1
camera wifi: got ip:192.168.31.91
```

- STA：`Xiaomi_037C`，IP **192.168.31.91**；
- AP：`ESP32S3-UVC`，**192.168.4.1**；
- 本机验证：`http://192.168.31.91/` → **HTTP 200，13659 B，title “ESP32-S2 UVC Demo”**；
- 摄像头仍 `0/0`，页面能开、视频空白；
- 注意：示例串口会打印 `connect to ap ... password:...`，不要把串口日志公开。
