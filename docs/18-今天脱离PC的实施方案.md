### 1.3 一个必须提前接受的取舍

这个工程是**独立固件**，烧上去之后，现有 Arduino 固件里的红外学习、定时任务、OLED、色温调光**都不在**。

原因：esp-sr 塞不进 Arduino 工程（本机 framework 没有 `ESP_SR` 库），必须在 IDF 里重写。所以今天的版本只做一件事：

> **说「开灯」→ GPIO5 的灯亮；说「关灯」→ 灭；拔掉 USB 用充电头供电，照样工作。**

这就是"插电即用"的最小闭环。剩下那些功能等 `docs/11` 的整机硬件到齐再合并回来。

### 1.4 唤醒词这件事，官方有硬性要求

esp-sr 官方文档原文：

> **Speech command recognition must be used with WakeNet. After wake-up, MultiNet detection can start.**

也就是说标准用法是**两段式**：

```
「你好小智」 → （灯闪一下 / 提示）→ 「开灯」 → 灯亮
```

不是「说开灯就开灯」。这会让体验比 A 路（PC Vosk）差一点，但换来的是完全离线。

工程里我留了一个开关（`GATE_BY_WAKEUP`）：

| 模式 | 说法 | 误触发 | 适用 |
|---|---|---|---|
| `1` 唤醒门控（官方推荐） | 先说唤醒词，再说命令 | 低 | 正常使用 |
| `0` 常开 | 直接说「开灯」 | **高** | 安静房间自测 |

先按 `1` 跑通（这是官方保证能工作的路径），确认能识别后，如果你觉得两段式太麻烦，再改 `0` 试。**不要一上来就用 `0`**——误触发时你分不清是"识别太灵敏"还是"代码有问题"，`docs/13` 那九个坑一半是这么来的。

中文唤醒词可选：「你好小智」（`wn9_nihaoxiaozhi`）、「Hi 乐鑫」（`wn9_hilexin`）、「小爱同学」（`wn9_xiaoaitongxue`）。默认用第一个。

## 三、cmd 命令（逐段复制）

### 3.0 一个必须知道的限制

**IDF 不支持 Git Bash。** 我实测过：

```
ERROR: MSys/Mingw is not supported.
ERROR: Activation script failed
```

所以下面的命令**必须在 `cmd.exe`（或双击 .bat）里跑**，不要用 Git Bash / WSL / MSYS。

### 3.1 一次性准备：环境变量

`export.bat` 会自己去猜 Python 版本，而本机 PATH 里的 `python` 是 3.13，IDF 会去找不存在的 `idf5.4_py3.13_env` 然后报错。必须先钉死用哪个 venv：

```bat
set "IDF_PATH=D:\Espressif\frameworks\esp-idf-v5.4.3"
set "IDF_PYTHON_ENV_PATH=D:\Espressif\python_env\idf5.4_py3.11_env"
```

这两行只在当前 cmd 窗口有效。关窗就要重设——所以我做了 §3.2 的包装脚本。

### 3.2 包装脚本（推荐，省掉每次设环境）

新建 `firmware\idf\lamp_sr\idf.bat`（仓库里已经生成，已实测通过）：

```bat
@echo off
set "IDF_PATH=D:\Espressif\frameworks\esp-idf-v5.4.3"
set "IDF_PYTHON_ENV_PATH=D:\Espressif\python_env\idf5.4_py3.11_env"
rem clear MSYS traces, otherwise export.bat refuses to run
set "MSYSTEM="
set "SHELL="
set "TERM="
call "%IDF_PATH%\export.bat" >nul 2>&1
idf.py %*
```

**这个文件必须保持纯 ASCII**，中文注释会让 cmd 把命令行拆断（见 §10.1）。

之后所有操作都通过它，不再碰环境变量：

```bat
cd /d "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr"
idf.bat --version
```

期望输出：

```
ESP-IDF v5.4.3-dirty
```

### 3.3 设目标芯片（只做一次）

```bat
cd /d "D:\study lamp\lamp\lamp\firmware\idf\lamp_sr"
idf.bat set-target esp32s3
```

这一步会顺带下载 `espressif/esp-sr` 组件（首次约 126 MB，含所有语言的模型）。**慢是正常的，不要中断。**

下载完成后 `managed_components\` 下会出现 `espressif__esp-sr\`。

### 3.4 编译

```bat
idf.bat build
```

首次编译 5~15 分钟（esp-sr 的库和模型打包占大头）。成功的标志：

```
Project build complete. To flash, run:
 idf.py flash
```

产物：

| 文件 | 烧到哪 |
|---|---|
| `build\lamp_sr.bin` | factory 分区（0x10000） |
| `build\srmodels\srmodels.bin` | **model 分区**（自动烧，别手动挑） |
| `build\partition_table\partition-table.bin` | 0x8000 |

### 3.5 烧录 + 看串口

```bat
idf.bat -p COM5 flash monitor
```

- `COM5` 换成你实际的串口（A 路用的是 COM5，通常不变）
- `flash` 会自动带上 `srmodels.bin`，不用单独烧
- `monitor` 里退出是 `Ctrl + ]`

### 3.6 说话

串口出现这一行才算真的跑起来了：

```
LAMP-SR ready, say "da kai deng" / "guan deng"
```

然后对着 INMP441 说 **「开灯」**。期望：

```
MN: id=1 text="da kai deng"  -> LED ON
```

说 **「关灯」**：

```
MN: id=3 text="guan deng"    -> LED OFF
```

### 3.7 拔掉 PC（今天最关键的一步）

1. 拔掉 USB
2. 插 5V 充电头（或充电宝）
3. 等 2 秒，说「开灯」

灯亮 = **脱离 PC 成功**。到这一步，A 路那台 PC 就可以彻底不用了。

## 四、本次实际踩到的坑（都是真实报错，不是推测）

这一节是实施过程中逐个撞出来的，按出现顺序记：

### 4.0 Git Bash 一律不能用

```
ERROR: MSys/Mingw is not supported.
ERROR: Activation script failed
```

IDF 主动拒绝 MSYS。所有命令必须在 `cmd.exe` 里执行。

### 4.1 `export.bat` 会猜错 Python

PATH 里的 `python` 是 3.13，IDF 于是去找 `idf5.4_py3.13_env`，而本机只有 `idf5.4_py3.11_env`：

```
ERROR: ESP-IDF Python virtual environment "...idf5.4_py3.13_env\Scripts\python.exe" not found
```

必须显式钉死 `IDF_PYTHON_ENV_PATH`。`idf.bat` 已经写死，所以直接用 `idf.bat` 就不会碰到。

### 4.2 esp-sr 2.6.1 把头文件改名了

网上教程（包括 2.0/2.1 时代的示例）都写 `#include "esp_mn_commands.h"`，2.6.1 里**这个文件不存在**。实际是：

| 旧 | 2.6.1 |
|---|---|
| `esp_mn_commands.h` | **`esp_mn_speech_commands.h`**（在 `src/include/`） |
| `esp_mn_commands_add(int, char *)` | `esp_mn_commands_add(int, const char *)` |

### 4.3 2.6.x 必须先 `alloc` 再 `add`

`esp_mn_commands_add()` 之前必须调用：

```c
esp_mn_commands_alloc(multinet, model_data);
```

否则 `add` 返回 `ESP_ERR_INVALID_STATE`，而日志里只会看到"命令没生效"，很难定位。

### 4.4 `CONFIG_SR_MN_CN_NONE` 是默认值

`set-target` 之后生成的 `sdkconfig` 里：

```
CONFIG_SR_MN_CN_NONE=y
# CONFIG_SR_MN_CN_MULTINET7_QUANT is not set
```

也就是**一个中文命令词模型都没有**。这时 `esp_srmodel_filter(models, ESP_MN_PREFIX, ESP_MN_CHINESE)` 返回 `NULL`，程序会在初始化阶段直接退出。

### 4.5 改了 `sdkconfig.defaults` 不会自动生效

`set-target` 已经生成了 `sdkconfig`，之后改 `sdkconfig.defaults` **完全没用**。必须删掉 `sdkconfig` 再 build：

```bat
del sdkconfig
idf.bat build
```

这一条最容易浪费时间：配置改了、看起来也改了，但编译进去的还是旧值。

## 五、三个必踩的坑（都会伪装成"别的问题"）


### 坑 1：分区表里必须有一个叫 `model` 的分区

esp-sr 在 **CMake 阶段**就去查，查不到直接中断：

```
Failed to find model in partition table file
```

不是运行时错误，是配置错误。本工程的 `partitions.csv` 已经写好：

```
factory,  app,  factory, 0x10000,  3M,
model,    data, spiffs,  ,         6M,
```

注意 `SubType` 必须是 `spiffs`，`Type` 必须是 `data`。

### 坑 2：PSRAM 不开也能编译、能烧，然后一运行就无限重启

日志：

```
SR_RINGBUF: Memory exhausted
```

反复重启，**完全看不出和 PSRAM 有关**。本工程 `sdkconfig.defaults` 已经写了：

```
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_SPIRAM_SPEED_80M=y
```

本板是 8 MB **octal** PSRAM，`MODE_OCT` 不能省。

### 坑 3：INMP441 必须 32 bit 槽，不能 16 bit

`pdm_mic.cpp:66-73` 已经踩过一次并写了注释：

> INMP441 输出 24 bit、MSB 对齐在 32 bit 槽里，且要求 WS 周期 64 BCLK（每声道 32 bit）。用 16 bit 槽只有 32 BCLK，麦克风会错位输出低频漂移。

本工程沿用同一份配置（`I2S_DATA_BIT_WIDTH_32BIT` + `slot_mask=LEFT` + 读 int32 后 `>> 16`）。

### 9.6 如果灯不亮，按这个顺序查（不要跳）

1. **串口有没有 `*** wake word detected ***`？**
   - 有 → 唤醒通过，问题在命令词，跳到第 3 步
   - 没有 → 麦克风信号不够，看第 2 步
2. **说话时 `mic peak` 有没有上到 200 以上？**
   - 没有 → 麦克风没接好，或 INMP441 的 L/R 没接 GND
   - 有 → 唤醒词发音不对，试「你好小智」说慢一点
3. **唤醒成功但命令不认** → 拼音表里是 `da kai deng`，不是「开个灯」「把灯打开」。只能说这 5 句
4. **全都对但灯不亮** → 查 GPIO5 接线（HW-479 的 G 通道），或者 LED 极性

## 十、批处理文件的两个坑（你自己写 .bat 时会遇到）

### 10.1 .bat 里绝对不能有中文

我在 `idf.bat` 里写了中文注释，cmd 用 GBK 解析，直接把命令行拆断：

```
'uild' 不是内部或外部命令
'p' 不是内部或外部命令
[ERROR] export.bat failed
```

**批处理文件的注释也必须纯 ASCII。** 这个坑没有任何提示，只会给一串莫名其妙的碎片报错。

### 10.2 从 Git Bash 调 cmd，`export.bat` 会拒绝

```
This .bat file is for Windows CMD.EXE shell only.
```

明明就在 cmd 里跑却不认——因为 Git Bash 把 `MSYSTEM` / `SHELL` / `TERM` 传给了子进程。`idf.bat` 里已经清掉：

```bat
set "MSYSTEM="
set "SHELL="
set "TERM="
```

你在干净的 cmd 窗口里直接跑不会遇到，但写自动化脚本时一定会。
