# 17 脱离 PC 实施方案（板上 ESP-SR 离线识别）

> 目标：**拔掉电脑，插电就说话，说「开灯 / 关灯」灯就响应。**
> 状态：方案待确认。**未改任何固件代码。**
> 关联：`docs/16-离线语音开关灯方案.md`（三路对比）、`docs/12`（V0/V1/V2 评估）、`docs/15`（小智 + DeepSeek）。

---

## 〇、先把一件事说死：A 路不可能脱离 PC

这不是"再优化一下"的问题，是架构决定的：

```
A 路：INMP441 → ESP32 → WiFi → PC 的 Vosk → 文字 → (回传) → 点灯
                              ↑
                        识别器在这里。拔掉 PC，这一段就不存在了。
```

板子上没有识别器，所以 A 路**永远**要 PC 在场。要"插电就用"，只能在板子上放一个识别器，也就是 **B 路（ESP-SR）**。

但 A 路今天只要 1 小时，而且它能给你两样 B 路给不了的东西：**今天就有一盏能说话的灯**，以及一套**判定基准**（说 10 次中几次），用来衡量 B 路值不值那 4 天。

**所以本方案是两条并行：A 今天跑通当对照，B 四天后拔 PC。** 下面分别给命令。

---

## 一、A 路的 PC 命令（可直接复制，约 1 小时）

### 1.1 先改两处（这是阻塞，不改跑不通）

| 文件 | 改成什么 | 为什么 |
|---|---|---|
| `firmware/include/secrets.h` | `LAMP_VOICE_SERVER_HOST` 改成 PC 实际 IP | 现在写的 `192.168.42.97` 不存在；当前 PC 是 `192.168.100.199`（WLAN）或热点下的 `192.168.137.1` |
| `server/voice_server.py` | 加 `--no-llm` | `:257-262` 里 `cmd` 在 `brain.ask()` 之后才下发，Ollama 不在就直接 `return`，**灯永远不动** |

### 1.2 启动服务（第一个窗口）

```bat
cd /d "D:\study lamp\lamp\lamp\server"
venv\Scripts\python.exe voice_server.py --no-llm
```

期望输出：

```
INFO loading Vosk model: ...\models\vosk-model-small-cn-0.22
INFO Vosk model ready
```

### 1.3 先不接板子，模拟设备发音频（第二个窗口）

```bat
cd /d "D:\study lamp\lamp\lamp\server"
venv\Scripts\python.exe test_client_voice.py --wav kaitest.wav
```

期望：

```json
{"type":"asr","text":"开灯"}
{"type":"cmd","light":"on"}
```

**这一行过了，说明 ASR → 关键词 → cmd 全通，剩下的只是网络。** 没通就别往下走，问题一定在服务端。

### 1.4 烧板子（第三个窗口）

```bat
cd /d "D:\study lamp\lamp\lamp\firmware"
set PLATFORMIO_BUILD_FLAGS=-DLAMP_CLOUD_ASR=0
%USERPROFILE%\.platformio\penv\Scripts\pio.exe run -e lamp_s3 -t upload
%USERPROFILE%\.platformio\penv\Scripts\pio.exe device monitor -p COM5 -b 115200
```

（PowerShell 里第一行改成 `$env:PLATFORMIO_BUILD_FLAGS="-DLAMP_CLOUD_ASR=0"`）

烧完串口应出现：

```
[voice] target ws://192.168.100.199:8765/ (16 kHz mono s16le)
[wifi] connected ssid="English" ip=192.168.100.xxx
[voice] WebSocket connected -> ws://192.168.100.199:8765/
```

### 1.5 说话

串口输入 `voice listen`，然后说「开灯」。期望：

```
[ASR] heard: 开灯
[cmd] light=on pct=70
```

开/关各说 5 次，把命中数记下来。**这个数字是 §2 的验收基线**，也是决定要不要买 SU-03T 的依据。

## 二、B 路：真正脱离 PC 的实施方案

### 2.1 环境核查结果（本机已具备，不用装东西）

我逐项查过了，这是可以立刻开工的状态：

| 项 | 状态 |
|---|---|
| ESP-IDF | ✅ `D:\Espressif\frameworks\esp-idf-v5.4.3`（含 `export.bat / export.ps1 / export.sh`） |
| S3 工具链 | ✅ `D:\Espressif\tools\xtensa-esp-elf` |
| Python 环境 | ✅ `D:\Espressif\python_env\idf5.4_py3.11_env` |
| 组件仓库连通 | ✅ `components.espressif.com` 返回 200（3.3 s） |
| esp-sr 组件 | ⬜ 本地没有，首次 `add-dependency` 会拉 **约 126 MB** |
| 版本兼容 | ✅ esp-sr 2.x 要求 IDF ≥ 5.0，本机 5.4.3 满足 |

**关键事实（查证过的，不是推测）**：

- ESP32-S3 支持的中文命令模型：`mn5q8_cn`、`mn6_cn`、`mn7_cn`；其中 `mn7_cn` 仅 S3/P4/S31 可用 —— 我们是 S3，可以上最新的 mn7。
- MultiNet7 + AFE 在 S3 上的开销约 **32 KB RAM + 4.1 MB PSRAM，CPU 约 35%**。本板 8 MB octal PSRAM 够用。
- 分区表**必须**有一个标签叫 `model` 的分区。esp-sr 的 CMake 在编译期用 `partition_table_get_partition_info(... "--partition-name model" ...)` 去查，查不到直接报 `Failed to find model in partition table file`。这是第一个必踩的坑。
- `idf.py flash` 会自动把模型打进 `model` 分区；只改代码时用 `idf.py app-flash`，别每次都重烧模型。

### 2.2 四个里程碑（不要一口气全做完）

| 阶段 | 做什么 | 硬验收 | 预计 |
|---|---|---|---|
| **M1** | 新建 IDF 工程，跑通「说开灯 → 串口打印命令 ID」 | 串口出现 `command_id`，且**不改任何识别相关代码** | 半天 |
| **M2** | 把麦克风换成本板的 INMP441（32 bit 槽），命令表改成开灯/关灯/亮一点/暗一点 | 连说 10 次，≥ 8 次正确 | 半天 |
| **M3** | 接 GPIO 灯：命令 ID → 亮度（复用现有 `lighting` 的取值） | 说「开灯」灯亮，「关灯」灯灭 | 1 天 |
| **M4** | 与主固件合并（或让 IDF 工程接管），拔掉 USB 用充电头供电 | **不插电脑，插电即用** | 1 天 |

M1 的意义：把"工具链/模型/分区"和"麦克风/代码"彻底分开验证。`docs/13` 九个坑里五个都是这两类问题混着查出来的。

### 2.3 M1 的具体命令

```bat
:: 1. 进 IDF 环境（这个窗口后面都用它）
D:\Espressif\frameworks\esp-idf-v5.4.3\export.bat

:: 2. 建工程
cd /d "D:\study lamp\lamp\lamp\firmware\idf"
mkdir lamp_sr && cd lamp_sr
```

`CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.16)
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(lamp_sr)
```

设定目标 + 拉组件：

```bat
idf.py set-target esp32s3
idf.py add-dependency "espressif/esp-sr^2.5.4"
```

`partitions.csv`（16 MB flash 的实际预算）：

```
# Name,   Type, SubType, Offset,   Size, Flags
nvs,      data, nvs,     0x9000,   0x6000,
phy_init, data, phy,     0xf000,   0x1000,
factory,  app,  factory, 0x10000,  3M,
model,    data, spiffs,  ,         6M,
```

> 3M app + 6M model = 9 MB，16 MB 还剩 7 MB。**代价是没有 OTA 双槽了**——这个工程阶段只求拔掉 PC，OTA 以后再说。
> 如果 mn7 装进去后 6M 不够，改 `model` 为 `8M` 并把 `factory` 压到 `2M`（IDF 版 app 约 1.2~1.5 MB，2M 够）。

`sdkconfig.defaults`：

```
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y
```

> PSRAM 这行是**第二个必踩的坑**：不开也能编译、也能烧，但一运行 AFE 就 `SR_RINGBUF: Memory exhausted` 然后无限重启。日志里看不出和 PSRAM 有关，很好骗人。

### 2.4 代码骨架（以官方中文示例为基准，别自己发明）

官方示例：`esp-skainet/examples/cn_speech_commands_recognition/main/main.c`（约 4.9 KB），结构是标准的两任务：

```c
#include "esp_afe_sr_iface.h"
#include "esp_afe_sr_models.h"
#include "esp_mn_iface.h"
#include "esp_mn_models.h"
#include "model_path.h"

srmodel_list_t *models = esp_srmodel_init("model");          // 读 model 分区

afe_config_t *cfg = afe_config_init("M", models,             // 单麦 → "M"
                                    AFE_TYPE_SR, AFE_MODE_LOW_COST);
afe_handle = esp_afe_handle_from_config(cfg);

// feed 任务：int n = afe_handle->get_feed_chunksize(afe_data); 别硬编码 1024
// detect 任务：
char *mn_name = esp_srmodel_filter(models, ESP_MN_PREFIX, ESP_MN_CHINESE);
esp_mn_iface_t *multinet = esp_mn_handle_from_name(mn_name);
model_iface_data_t *md = multinet->create(mn_name, 6000);     // 6000 = 6 s 超时
esp_mn_commands_update_from_sdkconfig(multinet, md);          // 命令表来自 menuconfig
assert(multinet->get_samp_chunksize(md) == afe_handle->get_fetch_chunksize(afe_data));
```

四个必须照抄的点：

1. `input_format` 用 `"M"`（我们只有一颗麦）。原示例走开发板 BSP 的 `esp_get_input_format()`，我们没有 BSP，直接给字面量。
2. `get_feed_chunksize()` 返回多少就喂多少，**不能自己定帧长**（原示例断言 `mu_chunksize == afe_chunksize`，写错就是断言重启）。
3. 命令表走 menuconfig（`esp_mn_commands_update_from_sdkconfig`），这样不用碰命令字符串格式。
4. 命令字符串到底填拼音还是汉字，**以所装 esp-sr 版本的 Kconfig 提示为准**——`mn7_cn` 与老的 `mn5q8_cn` 在这一块格式不同，我不想让你在这上面卡两天。M1 跑通时顺便把实际格式记进本文档。

### 2.5 本板的三个硬件坑（都是已经在仓库里踩过的）

**坑 1：INMP441 必须用 32 bit 槽。** `pdm_mic.cpp:66-73` 写着原因：16 bit 槽只有 32 BCLK，而 INMP441 要求 WS 周期 64 BCLK，否则数据错位、读数极小甚至全 0。IDF 工程的 I2S 初始化要照搬这段，不能抄示例里开发板的 16 bit 配置。

**坑 2：引脚是 BCLK=16 / WS=18 / SD=17**（`config.h:65-67`），不是官方开发板的默认脚。原示例的 `esp_board_init()` 整段不能用，只能抄它的两个任务函数。

**坑 3：单麦没有 AEC。** 现在没有喇叭，所以不影响；**等 MAX98357 到了，一放音就会自己听见自己**，那时才需要 `"MR"` 格式和 AEC 参考通道。这一步现在别做，做了也验证不了。

## 三、时间与代价

| | A 路（PC） | B 路（板上） |
|---|---|---|
| 出结果 | **1 小时** | 4 天 |
| 插电即用 | ❌ | ✅ |
| 要 API Key | 不要 | 不要 |
| 识别范围 | 任意中文（Vosk 通用模型） | 固定命令词（约 300 条内） |
| 依赖 | PC 开机 + 同网段 | 无 |
| 主固件影响 | 只加一个编译宏 | 红外/定时/舵机要重写进 IDF 工程 |

**B 路最大的隐藏成本不是识别，是"主固件搬家"**：`main.cpp` 842 行里的红外学习、定时任务、舵机、OLED 都不在 IDF 工程里。所以 M4 我建议**先只让 IDF 工程管"语音+灯"**，其余功能留在 Arduino 固件里——两套固件分板跑，或者等 `docs/11` 的整机硬件到齐后一次性合并。

## 四、风险

| 风险 | 概率 | 症状 | 应对 |
|---|---|---|---|
| model 分区没被识别 | 高 | 编译报 `Failed to find model in partition table file` | 分区表必须叫 `model`，且 `board_build.partitions`/`PARTITION_TABLE_CUSTOM` 指向自定义文件 |
| PSRAM 没开 | 高 | 启动即 `SR_RINGBUF: Memory exhausted` + 无限重启 | `CONFIG_SPIRAM=y` + `CONFIG_SPIRAM_MODE_OCT=y` |
| 命令词格式填错 | 中 | 一直 `ESP_MN_STATE_DETECTING`，永不出结果 | 用 menuconfig 的命令表，对照组件 Kconfig 提示 |
| I2S 槽宽抄错 | 中 | 识别率极低、日志里全是 detecting | 照搬 `pdm_mic.cpp` 的 32 bit 槽 |
| esp-sr 首次下载慢 | 中 | `add-dependency` 卡住 | 组件仓库已实测 200/3.3 s，可重试；也可先手动 `git clone` 放 `components/` |
| 6M 分区不够 | 低 | 编译报模型放不下 | factory 压到 2M，model 提到 8M |

## 五、我的建议

1. **今天先把 §1 跑完**（1 小时）。这一步不改固件逻辑，风险极低，而且拿到"说 10 次中几次"这个数字。
2. **然后立刻开 M1**（半天）。M1 不碰你的主固件，只在新目录 `firmware/idf/lamp_sr/` 里验证 esp-sr 能不能在这块板子上识别出中文命令。M1 失败了也只损失半天，主固件毫发无损。
3. **M2 通过后再决定 M3/M4**。如果 M2 的命中率只有 5/10，那说明单麦近场条件不够，要先解决麦克风（加海绵套/改增益/换双麦），而不是继续写代码。

**需要你点头的只有一件事**：是否允许我新建 `firmware/idf/lamp_sr/` 这个并行工程（不动现有任何文件）。允许的话我现在就从 `export.bat` + `add-dependency` 开始，M1 预计今天内能给你一句"识别到了"。
