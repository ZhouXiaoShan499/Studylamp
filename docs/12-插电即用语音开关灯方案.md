# 12 插电即用语音开关灯方案（Rev B · 按实际台架接线改写）

> 目标不变：**插上电源，对着麦克风说「开灯 / 关灯」，灯就响应**。
> Rev B 的改动：按你实际在用的接线重写——**+ 轨只有 3V3，严禁 5V 上轨**，麦克风用 INMP441，灯只有 HW-479 的 G 通道。
> 上一版按「5V 灯板 + 5V 语音模块」写的假设作废。

---

## 一、一句话结论

**你的接线已经够用了，缺的不是硬件，是两件事：把 HW-479 剩下的 R/B 用起来，以及把语音从「连电脑」换成「板载离线识别」。**

- 灯：**L0 就在你手上**（HW-479），L1 才需要外接灯 + MOS，L2 才碰 220V。
- 语音：**V0 按键（今天可用）→ V1 离线模块（1 天）→ V2 ESP-SR（3~4 天，纯 3.3V，不加硬件）**。
- 三条红线不动：+ 轨只走 3V3；5V 一律飞线不落轨；220V 不上面包板。

## 二、Rev B 相对上一版改了什么

| 项 | 上一版（作废） | Rev B（按实际） |
|----|----------------|------------------|
| 供电 | 5V/2A 进 + 轨 | **3V3 进 + 轨**，5V 只允许飞线 |
| 灯 | 5V 灯板 + AO3400 | L0 用 HW-479 G 通道；L1 才外接灯 + MOS |
| 语音模块 | 直接 5V 供电 | 5V 从开发板 5V 脚**单独飞线**，不落轨 |
| 麦克风 | 新增 INMP441 | 已接好，V2 直接复用 |
| 蜂鸣器 | 默认有 | **不加**，用 HW-479 的 B 通道做提示 |

## 三、先核对你现在的台架（三个坑）

### 坑 1：GPIO5 默认只有 56% 亮度

`lighting.cpp` 是双通道色温混光。默认 CCT 4300K 时 **暖 58% / 冷 56%**，而你的 G 接在 GPIO5 = 冷通道 → 绿灯只拿到 56% 的占空比。

```text
light 100        → G 亮到 56%，看着"没那么亮"
cct 6500
light 100        → G 亮到 100%
```

**这不是故障，是色温混光的正常结果。** 想让"开灯"就是全亮，见 §7 的单通道模式。

### 坑 2：主固件的按键是硬编码低有效

`main.cpp:48` 是 `pinMode(pin, INPUT_PULLUP)`，`main.cpp:57` 判断 `digitalRead == LOW` 才算按下。

- 你的 HW-483 是 `+ → 3V3 / S → GPIO4`，**如果模块是"上拉到 3V3 + 按键拉低"，代码正好匹配**；
- 如果是"下拉 + 按键拉高"，主固件会**永远读到按下**（或永远读不到），按键等于废的。

2 秒验证：

```powershell
pio run -e bringup -t upload
pio device monitor -b 115200
```

bringup 的 `BRINGUP_MODE=1` 会打印 `[btn] raw=`。**松开手应该是 1，按下是 0**；如果反过来，把 `BTN_ACTIVE_LOW` 改 0、`BTN_USE_PULLUP` 改 0 再烧。主固件没有这个开关，需要自己加（见 §7）。

> 先把这条确认掉，否则后面"语音和按键都不灵"会查错方向。

### 坑 3：HW-479 的 R/B 悬空，白扔两个通道

`config.h` 在面包板模式下**正好**留了两个空脚：

| 通道 | 引脚 | 代码里的身份 | 建议接法 |
|------|------|--------------|----------|
| G | GPIO5 | `PIN_LED_COOL` 冷白 | 保持不动 |
| **R** | **GPIO21** | `PIN_LED_WARM` 暖白（面包板模式专门挪到 21） | **接上**，2700K 时亮 |
| **B** | **GPIO14** | `PIN_STATUS_LED` 状态灯 | **接上**，聆听/执行时闪 |

接上以后，**一行代码都不用改**：

```text
cct 2700  → R 亮（暖）
cct 6500  → G 亮（冷）
cct 4300  → R+G 同时亮（偏黄）
思考/执行 → B 闪
```

这比"只有一个绿点"信息量大得多，而且把 `config.h` 里那三个定义全用上了。

## 四、灯：L0 → L1 → L2，+ 轨始终是 3V3

### L0 · 台架指示灯（今天，￥0）

HW-479 三通道接 GPIO5 / 21 / 14（见上表）。用途：**验证整条链路通不通**。
能开、能关、能调、能变色温，L0 就算完成。

### L1 · 真正的灯（￥20~30，推荐停在这一级）

外接 5V USB 灯板 / 12V 灯带 + 逻辑电平 MOS。**灯的电源是独立的第二路，只共地，不进 + 轨**。

```text
   独立 5V/12V 电源 + ──────┬──── 灯板 +
                            │
   GPIO5 ──100Ω──┐          │
                 │          │
              ┌──┴──┐       │
              │ MOS │───────┴──── 灯板 −
              └──┬──┘
                 │
   独立电源 GND ─┴──── ESP32 GND（必须共地）
   栅极再加 10k 下拉到 GND  ← 保证插电瞬间不闪
```

- MOS 选 **AO3400**（<2A）或 **IRLZ44N**（12V / 大电流），必须是**逻辑电平**管，普通 IRF540 在 3.3V 栅压下打不开。
- 接线顺序：先断电、先接 GND、最后接栅极。接错顺序最容易打穿栅极。
- **接 MOS 之前必须把 HW-479 的 G 线拔掉**——GPIO5 一脚一用，不能既驱 LED 又驱栅极。

### L2 · 220V 台灯（不建议，除非你很清楚自己在做什么）

- **220V 绝不上面包板**，任何情况下都不。
- 只用成品 5V 光耦继电器模块（自带续流、10A/250VAC），继电器线圈的 5V 单独供电，**不得从 + 轨取电**。
- 火线串常开触点、零线直通、加 1A 保险丝、全部塞进阻燃盒、端子不外露。
- 继电器默认多是**低电平触发**，固件要加 `LAMP_RELAY_ACTIVE_LOW`，否则上电瞬间灯会"啪"一下全亮。
- 继电器**只能开关，不能调光**。220V 调光要过零检测 + 可控硅，本期不做。

## 五、语音：V0 → V1 → V2

### V0 · 按键触发（今天，￥0，不算语音但是必经）

先用 GPIO4 短按做 `lighting::toggle()`。**这一步的目的是把"灯"和"按键"两条独立变量先钉死**，再去加语音。灯和语音同时出问题，排障会翻倍。

### V1 · 离线语音模块（1 天，￥15~25，最省事）

| 项 | 规格 |
|----|------|
| 模块 | SU-03T / CI-03T 一类，自带麦克风，可自定义中文命令词 |
| 供电 | **5V，从开发板 5V 排针单独飞线**，绝不落 + 轨 |
| 信号 | 模块 TX → **GPIO47**（3.3V 电平，直连，不需要分压） |
| 接线 | 3 根：5V / GND / TX，单向即可 |
| 电流 | 60~200 mA（带喇叭时更高）→ 必须用 5V/2A 适配器，别用电脑 USB 口 |

> 买之前确认是 5V 版本；少数 3.3V 核心板存在，但 3V3 轨带不动它的功放。

**代价**：多一颗模块，语音能力锁死在固定命令词，且 INMP441 就闲置了（两条语音路径二选一，不要同时接）。

### V2 · ESP-SR 板载离线识别（3~4 天，￥0，用你已接的麦克风）

| 步骤 | 内容 | 风险 |
|------|------|------|
| 0 | **先验麦克风电平**（见下） | **P0，不过这条后面全废** |
| 1 | 新建 `firmware/idf/lamp_sr/`，target=esp32s3，加 `espressif/esp-sr` | 首次拉依赖慢 |
| 2 | 分区表加 `model` 分区约 2 MB（16 MB flash 够） | 写错会反复重启 |
| 3 | I2S 32 bit 槽 → 右移 16 位转 int16，16 kHz | 移位量错就是纯噪声 |
| 4 | AFE 单麦：`mic_num=1, ref_num=0`，每次喂 32 ms / 512 样本 | 参数不对识别率断崖 |
| 5 | MultiNet6 中文命令词（8 条，拼音配置）+ 可选 WakeNet 唤醒 | 自定义唤醒词要训练 |

**Step 0 必须做**：串口执行 `mic test 10`，正常说话时峰值应该落在 **3000~30000**（int16 域）。

`config.h` 里记着"说话峰值 ~56（增益 4 之后）"——如果实测真是这个量级，说明信号比正常低 30 dB 以上，**MultiNet 一定识别不出来**。先排查：

1. 量 + 轨实际电压，USB 供电跌落时可能只有 3.0 V；
2. INMP441 的 L/R 是否真的压到 GND（悬空 = 右声道 = 全 0）；
3. 麦克风孔有没有被助焊剂堵住；
4. 加数字增益（16~32）并限幅，再测一次。

**为什么不建议在 Arduino 下硬上 ESP-SR**：它只以 ESP-IDF 组件形式发布，Kconfig 依赖多，塞进 Arduino 工程几乎无解。而 `firmware/idf/lamp_voice/sdkconfig` 里写的是 `CONFIG_IDF_TARGET="esp32"`，**不是 S3**，那个工程只能当参考，必须重建。

## 六、终版接线表

### 电源（红线区）

| 线 | 从 | 到 | 规则 |
|----|----|----|------|
| 3V3 | 开发板 3V3 | 面包板 **+ 轨** | 唯一允许上 + 轨的电源 |
| GND | 开发板 GND | 面包板 **− 轨** | 所有地最终汇到 − 轨 |
| 5V | 开发板 5V 排针 | 语音模块 VCC | **飞线，永远不落轨**，用红/黄色线区分 |
| 外部灯电源 | 独立适配器 | 灯板 + MOS | 只共地，不进 + 轨 |

### 模块

| 模块 | 引脚 | 接到 |
|------|------|------|
| HW-483 按键 | + / − / S | + 轨 / − 轨 / **GPIO4** |
| HW-479 RGB | − | − 轨 |
| | **G** | **GPIO5**（冷通道） |
| | **R** | **GPIO21**（暖通道，新增） |
| | **B** | **GPIO14**（状态灯，新增） |
| INMP441 | VDD / GND | + 轨 / − 轨 |
| | L/R | **− 轨（GND）= 左声道**；接 VDD 就是右声道，代码只读左声道 → 全 0 |
| | SCK / WS / SD | **GPIO16 / GPIO18 / GPIO17** |
| 离线模块（V1） | VCC / GND | 开发板 **5V 飞线** / − 轨 |
| | TX | **GPIO47** |

> HW-479 针序是 `− R G B`，`−` 丝印那端算第 1 脚。插错一格绿灯永远不亮——这是 `docs/06` 里已经踩过的坑。

### + 轨电流预算

| 负载 | 电流 | 上 + 轨？ |
|------|------|-----------|
| INMP441 | ~1.6 mA | ✅ |
| HW-479 三通道 | ~15 mA | ✅ |
| 有源蜂鸣器 | 15~30 mA | ⚠️ 可，但本方案不加 |
| 继电器线圈 | 70~90 mA | ❌ 独立 5V |
| 5V 灯板 | 200~1000 mA | ❌ 独立电源 |
| 离线语音模块 | 60~200 mA | ❌ 5V 飞线 |

**+ 轨外部负载控制在 50 mA 以内**。开发板 3V3 由板载 LDO 提供，扣掉 ESP32-S3 自己（WiFi 峰值 ~350 mA），余量不多。

## 十、电气红线（贴在面包板旁边）

1. **+ 轨只许 3V3。** 任何 5V 一律飞线，线色区分，永不落轨。
2. **灯、继电器、喇叭不从 + 轨取电。** 它们要的是电流，不是电压。
3. **220V 不上面包板。** 面包板不是强电设备。
4. **GPIO5 一脚一用。** 接 MOS 前先拔 HW-479 的 G 线。
5. **改线一律断电。** 带电插拔最容易打穿 MOS 栅极和 I2S 输入。
