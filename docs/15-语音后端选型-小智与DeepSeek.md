# 15 语音后端选型：小智 + DeepSeek 官方 API

> 回答一个问题：能不能「小智 + DeepSeek 官方 Key」？
> **能，而且这是目前唯一能只用一个 Key 就跑通「能听会说」的路。**
> 但 DeepSeek 没有语音识别——这个 Key 只买到「脑子」，「耳朵」是小智服务端自带的。

- 日期：2026-11-08
- 取代：`docs/14-腾讯云语音链路改造方案.md` 的前提（腾讯 TC3 签名那一套在本路线下**不需要做**）
- 对齐：`docs/11-AI学习机器人产品定位与开发规划.md`（产品已从「台灯」改为「能听会说会动的学习机器人」）

## 一、先纠正一个前提：DeepSeek 官方 API 没有耳朵

| 项 | 事实 |
|---|---|
| base_url | `https://api.deepseek.com` |
| 路径 | `/chat/completions`（OpenAI 兼容，加 `/v1` 也能通） |
| 当前模型 | **`deepseek-flash`**（由 V4.1-Flash-1017 提供）、`deepseek-v4-pro` |
| 已下线 | `deepseek-chat` / `deepseek-reasoner`（旧的 V3.x 别名，官方已不建议使用） |
| 音频输入 | **不支持**。纯文本 in / 纯文本 out |

所以「只用 DeepSeek 一个 Key 做语音助手」这件事，**单独拿出来是不成立的**——它能判动作、能回答，但听不懂麦克风。

这也解释了为什么阿里云和腾讯云方案都要额外一套 ASR 凭据：不是设计得啰嗦，是「耳朵」本来就属于另一条产品线。

---

## 二、小智补上了「耳朵」和「嘴」

小智（xiaozhi-esp32）不是库，是一整套「固件 + 服务端」：

```
ESP32-S3 固件                服务端（PC / 云服务器）
─────────────────           ────────────────────────────
离线唤醒（ESP-SR）    ──WS──>  ASR（本地 SenseVoice / FunASR）
Opus 编码 / VAD              LLM  ← 这里接 DeepSeek 官方 Key
回声消除                      TTS（EdgeTTS，免费无需 Key）
设备端 MCP  ──JSON-RPC──>     工具调用：LED / 舵机 / GPIO / 屏幕
```

关键点：**ASR 和 TTS 都在服务端本地跑，不需要任何云厂商 Key。**
- ASR：SenseVoice / FunASR，CPU 上就能实时，中文识别质量明显好于 Vosk
- TTS：EdgeTTS，免费、无需账号

于是「一个 DeepSeek Key」真的够了。这是它和腾讯云方案最大的差别。

---

## 三、三条路摆在一起

| | A 现有固件 + 腾讯 ASR | B 现有固件 + PC 服务端 | **C 小智 + DeepSeek** |
|---|---|---|---|
| 需要的凭据 | 腾讯 2 个 + DeepSeek 1 个 | DeepSeek 1 个 | **DeepSeek 1 个** |
| 必须常开服务端 | 否 | 是（PC） | 是（PC 或云，可托管） |
| 唤醒词 | 无（按键） | 无（按键） | **有，离线唤醒** |
| TTS 说话 | **没有** | 有（PC 侧） | **有** |
| 打断 / 流式 | 无 | 无 | **有** |
| 设备控制 | 现有代码 | 现有代码 | **要重写成 MCP 工具** |
| 工作量 | 半天（含自签 TC3） | 1 小时 | 2~3 天（含硬件适配） |
| 对 docs/11 的契合度 | 低（机器人不会说话） | 中 | **高** |

一句话：**A 解决欠费，B 验证 Key，C 才是产品形态。**

---

## 四、但今天不该立刻迁小智

三个硬条件没到位，现在迁就是空转：

| 条件 | 现状 | 影响 |
|---|---|---|
| 扬声器 + MAX98357A | **未到货**（docs/11 §5.2 标注 ⬜） | 小智的核心是「说」，没喇叭等于废掉一半 |
| TFT 屏 / 总线舵机 / 灯环 | 未到货 | 小智的设备端 MCP 没有可控制的实体 |
| ESP-IDF 版本 | 本地 v5.4.3 | 小智要 v6.0.x，得先升级工具链 |

`docs/11 §5.4` 的阶段门原则写得很清楚：**硬件不到位时，只做不依赖该硬件的软件工作**。现在迁小智，等于拿开发板「假装」整机验收。

还有一条更现实的：一旦迁到小智，现有固件里那 3000 多行（照明、调光、红外学习、色温）**大部分要丢**——因为 docs/11 已经把照明取消了。这件事迟早要做，但不该由「阿里云欠费」这个 5 分钟能解决的问题来触发。

## 五、推荐路线：三步，今天只做第一步

### Step 1（今天，30 分钟）：PC 服务端换 DeepSeek，验证 Key 通

不碰固件，只改 `server/voice_server.py`：

- 现在的 `Brain` 类是 Ollama `/api/generate`
- 加一个 OpenAI 兼容分支：`https://api.deepseek.com/chat/completions`，`Bearer <key>`，`model=deepseek-flash`
- 固件按 `-DLAMP_CLOUD_ASR=0` 编，连 PC 的 WebSocket（现有代码，不用改）

**验收**：串口 `voice say 什么是机会成本` → 返回一段中文；`voice listen` 说「开灯」→ 灯亮。
**意义**：不花一分钱验证 DeepSeek Key、模型名、网络三件事，同时把阿里云彻底摘掉。

> 顺带修一个已经过期的地方：`config.h` 里 provider=2 的默认 `CLOUD_LLM_MODEL = "deepseek-chat"` 已经下线，应改成 `deepseek-flash`，路径建议同时从 `/v1/chat/completions` 改成 `/chat/completions`。这就是 `docs/13` 坑 6 的翻版——模型名当易耗品。

### Step 2（喇叭到货后，半天）：小智冒烟测试

- 接线：INMP441 + MAX98357A + 小喇叭（约 10 元）
- 编译 xiaozhi-esp32 的面包板配置，连自建服务端
- 服务端配 DeepSeek 官方 Key，ASR 选 SenseVoice 本地

**验收**：唤醒 → 说话 → 听到回答。这一步只验证「小智能不能在这块板子上跑」，不碰业务。

### Step 3（定版，2~3 天）：把机器人业务做成 MCP 工具

- 舵机：转头 / 点头
- 灯环 / 屏幕：聆听、思考、回答、计时四种状态
- 番茄钟：开始 / 暂停 / 查询（现有 `timer_task.cpp` 的逻辑可复用）
- 学习问答：DeepSeek + 学习场景提示词

到这一步，`docs/11` 的 P0 功能才算真正落地。

## 六、如果不想等硬件，也可以现在就上小智

可以，但要把代价认清楚：

1. 现在只能验证「听 → 想 → 串口打印」，**听不到回答**（没喇叭）；
2. 服务端要一直开着。想「插电即用」，得把 xiaozhi-server 部署到云服务器（约 50 元/月，1 核 2 G 够跑 SenseVoice）；
3. 官方云（xiaozhi.me）虽然免部署，但**不能用你自己的 DeepSeek Key**，模型和额度由官方控制——这跟你「直接调官方 API」的诉求冲突。

## 八、一句话总结

**「小智 + DeepSeek 官方 Key」是正确方向，一个 Key 也确实够——因为耳朵和嘴是小智服务端免费提供的。**
但它是一次底座迁移，不该在喇叭还没到货、被欠费逼着的时候做。
今天先把 PC 服务端接上 DeepSeek，30 分钟把 Key 验证掉；喇叭到了再迁小智。
