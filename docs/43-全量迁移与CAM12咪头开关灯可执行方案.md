## 2. 第一个决定：把"听"和"看"拆开（修正 41 号的一条依赖）

### 2.1 41 号说过严了

41 号 §0 写的是「CAM12 麦克风能控制灯，**前提是摄像头先枚举**」。这句话只在"咪头和摄像头是同一个 USB 设备"这层意义上成立，但**不成立的部分更重要**：

`usb_stream` 的三条流是**各自独立使能**的，源码里就是三段独立的 `if`：

| 流 | 使能条件 | 出处 |
|---|---|---|
| UAC 喇叭 | `spk_samples_frequence && spk_bit_resolution` | `usb_stream.c:3706` |
| UAC 咪头 | `mic_samples_frequence && mic_bit_resolution` | `usb_stream.c:3724` |
| UVC 摄像头 | `frame_width && frame_height` | `usb_stream.c:3744` |

也就是说：**只配 UAC、不配 UVC 是完全合法的配置**。官方示例本身也支持——`usb_camera_mic_spk` 把 `ENABLE_UVC_CAMERA_FUNCTION` 改成 0，就退化成纯音频工程。

所以正确的依赖关系是：

```text
开关灯  ←  UAC 咪头  ←  设备能枚举（D+ 上拉出现）
             ↑
        ✗ 不需要 UVC 出图
        ✗ 不需要 H.264/MJPEG 协商
        ✗ 不需要 45 KB×2 的帧缓冲
```

**41 号的"M2 依赖 M0"应改为：M2 依赖"枚举"，不依赖"UVC 兼容"。** 摄像头只支持高分辨率、只支持 High-Speed、MJPEG 不兼容——这些**都不会挡住用嘴开灯**。

### 2.2 拆完的架构

```text
                 ┌──────────────── audio_in.h（16 kHz / 单声道 / int16）────────────────┐
CAM12 UAC 咪头 ──┤ uac_mic.c：ringbuf → 降采样 48k→16k → int16                        │
（或 INMP441）   └ i2s_mic.c：I2S 32 bit 槽 → 右移 16 → 增益 ─────────────────────────┘
                                     │
                                     ▼
                        AFE（降噪/VAD/AGC）→ MultiNet（离线命令词）
                                     │              ↘ 云端 ASR（有网时）
                                     ▼
                        intent: on / off / up / down / max
                                     │
                                     ▼
                    LEDC 灯（GPIO5 冷白 / GPIO21 暖白） + 网页状态同步
```

**收益三条**：

1. **排期解耦**：摄像头硬件继续排查，语音链路照常推进，不必串行等；
2. **内存**：UVC 需要两块 45–55 KB 传输缓冲 + 一帧 PSRAM 缓冲；纯音频 < 64 KB。M1/M2 阶段不背这个包袱；
3. **可替换**：UAC 咪头不理想（噪声大/只有 48k/不暴露 UAC）时，换回 INMP441 只改一个编译宏，业务代码零改动。

## 3. 第二个决定：双轨迁移，不做大爆炸重写

### 3.1 为什么不能一次性重写

Arduino 版是**唯一拥有完整灯语义（WiFi + 网页 + 云 ASR + 定时 + 预设 + 红外）的镜像**。一次性推倒重写意味着：在 parity 通过之前，板子上没有可用固件，每天都是"全红"。

### 3.2 两条轨道

| 轨道 | 镜像 | 角色 | 什么时候烧 |
|---|---|---|---|
| **A 现状** | Arduino `lamp_s3_tencent` | 产品固件，仍是唯一"全功能" | 演示、救砖、对照 |
| **B 目标** | IDF `lamp_av` | 逐模块追平，追平一项切一项 | 每次里程碑验收 |

**切换门禁**：§8 的"必搬项"全绿之前，`lamp_av` 只当实验镜像，不替代 A 轨道。

### 3.3 搬完会丢的两样东西（必须提前认）

| 丢失项 | 原因 | 影响 | 处理 |
|---|---|---|---|
| **OTA 双槽** | Arduino 用 `default_16MB.csv`（`otadata` + `app0/app1`）；42 号的分区表是单 `factory` 3 MB | 以后升级只能插线烧 | 要保 OTA 就改成 `2×3 MB app + 6 MB model`，16 MB 刚好塞满、无余量；**建议先不要 OTA**，等 model 分区瘦身（见 §9） |
| **USB CDC 日志口** | Arduino `ARDUINO_USB_CDC_ON_BOOT=1`，日志走 GPIO19/20；Host 模式下这两脚归摄像头 | 日志必须改看 **UART0 / COM5**；一切"看 USB 串口"的习惯和脚本要换 | 已在 42 号固定：`CONFIG_ESP_CONSOLE_UART_DEFAULT=y` + `USJ` 关闭 |

> 顺带一个**白拿的好处**：Arduino 的 WiFi 凭据存在 NVS namespace `lampwifi`（key `nets/last/ssid/pass`），定时任务存在 `lamp1`（key `tasks/used`）。IDF 只要用**同样的 namespace 和 key**，`lamp_av` 第一次启动就能直接继承这些配置——**不用重新配网**（见 §6.7）。

## 5. CAM12 咪头开关灯：三条链路

| | **A 离线命令词** | **B 云 ASR + TTS** | **C INMP441 兜底** |
|---|---|---|---|
| 依赖 | esp-sr + 模型分区 | 网络 + 腾讯 Key | 无（只依赖麦克风） |
| 延迟 | < 500 ms | 1–3 s | < 500 ms |
| 花钱 | 0 | 按量计费 | 0 |
| 能说什么 | 5 条固定命令（开/关/亮/暗/最亮） | 自然语言 + 问答 | 同 A |
| 用哪个麦 | CAM12 UAC | CAM12 UAC | INMP441 |
| 现在能跑吗 | 识别代码齐，UAC 源未写、缺枚举 | 逻辑齐，未移植 | **✅ 现在就能跑** |

**推荐顺序：C 已有 → A 先做 → B 后做。** A 通了就证明"咪头 → 意图 → 灯"整条链在 IDF 里是通的，剩下的只是换一个音频源。

### 5.1 采样率 / 声道 / 位宽协商

`usb_stream` 不保证给 16 kHz。开机先把设备能力打印出来：

```c
size_t n = 0, cur = 0;
uac_frame_size_list_get(STREAM_UAC_MIC, NULL, &n, &cur);   // 先问有几项
uac_frame_size_t list[8];
uac_frame_size_list_get(STREAM_UAC_MIC, list, &n, &cur);   // 再取详细
// 每项含 ch_num / bit_resolution / samples_frequence / min / max
```

几种情况：

| 设备给什么 | 处理 |
|---|---|
| 直接有 16 kHz | 最优，直接用 |
| 有 32 kHz | 2:1 抽取 |
| 只有 48 kHz | 3:1 抽取（先做 3 点滑动平均抗混叠，跑通再换更好的滤波器） |
| 多声道 | 只取第 0 声道 |
| 24/32 bit | 右移到 16 bit |

也可以用 `uac_frame_size_reset(STREAM_UAC_MIC, 1, 16, 16000)` 主动要求 16 kHz——**必须在流挂起状态下调用**，恢复流之后才生效。

> 喇叭方向反之：esp-tts 输出 16 kHz，若 CAM12 喇叭只收 48 kHz，就要 ×3 线性插值，或在挂起状态把喇叭也 reset 到 16 kHz。

### 5.2 回声：先半双工，别一上来做 AEC

咪头和喇叭在**同一个模块**上，TTS 一响咪头立刻听到，会自己触发自己。`usb_stream` 已经给了现成开关：

```c
usb_streaming_control(STREAM_UAC_MIC, CTRL_SUSPEND, NULL);  // 播放前：挂起麦
/* … uac_spk_streaming_write() … */
usb_streaming_control(STREAM_UAC_MIC, CTRL_RESUME,  NULL);  // 播完：放开
// 也可用 CTRL_UAC_MUTE（参数 bool）与 CTRL_UAC_VOLUME（0–100）
```

**TTS（M5）之前不用管 AEC**——没有喇叭就没有回声。验收标准只有一条：TTS 播完后 5 秒内不出现第二次 `[ASR]`。

### 6.2 `audio_in.h`（整个方案的关键 20 行）

```c
#pragma once
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include "esp_err.h"

/* 全工程只认这一种格式：16 kHz / 单声道 / int16。
 * 采样率协商、位宽转换、降采样全部关在各实现内部。 */
#define AUDIO_IN_RATE 16000

typedef enum { AUDIO_SRC_UAC = 0, AUDIO_SRC_I2S } audio_src_t;

esp_err_t audio_in_start(audio_src_t src);
/* 阻塞读，凑满 samples 个采样点才返回；返回实际拿到个数（超时返回 0）。 */
size_t    audio_in_read(int16_t *pcm, size_t samples, uint32_t timeout_ms);
/* 半双工：TTS 播放期间关掉，避免自触发。 */
void      audio_in_set_enabled(bool on);
```

两个实现由 Kconfig 二选一，`audio_in_start()` 里分派。业务层**不包含**任何 `<usb_stream.h>` 或 `<driver/i2s_std.h>`。

### 6.3 `uac_mic.c` 要点

```c
/* ① mic 回调里绝不做重活：只入环形缓冲。官方注释就是 "cannot block in here!" */
static void mic_cb(mic_frame_t *f, void *arg)
{
    xRingbufferSend(s_rb, f->data, f->data_bytes, 0);   /* 0 等待，满了就丢 */
}

/* ② 独立任务：环缓冲 → 转 16k/单声道/int16 → 二次环缓冲，供 audio_in_read 取 */
static void uac_task(void *arg)
{
    uac_config_t cfg = {
        .mic_ch_num            = UAC_CH_ANY,
        .mic_bit_resolution    = UAC_BITS_ANY,
        .mic_samples_frequence = UAC_FREQUENCY_ANY,  /* 先任意，连上再 reset 到 16k */
        .mic_buf_size          = 8192,
        .mic_cb                = mic_cb,
        .spk_ch_num            = UAC_CH_ANY,
        .spk_bit_resolution    = UAC_BITS_ANY,
        .spk_samples_frequence = UAC_FREQUENCY_ANY,
        .spk_buf_size          = 16000,
    };
    uac_streaming_config(&cfg);
    usb_streaming_state_register(state_cb, NULL);   /* 在 CONNECTED 里打印能力表 */
    usb_streaming_start();
    usb_streaming_connect_wait(pdMS_TO_TICKS(30000));
    /* …循环: 取环缓冲 → 降采样 → 换算 int16 → 推送… */
}
```

### 6.4 接到 `lamp_sr` 的 AFE/MultiNet：只需改 6 行

## 9. 风险与回退

| 风险 | 概率 | 影响 | 处理 |
|---|---|---|---|
| **摄像头一直 `0/0`** | 中 | M6 卡住 | **不阻塞 M2**：走 INMP441 或先用 UAC（若设备能枚举） |
| CAM12 不暴露 UAC 输入 | 中 | 用不了它的咪头 | 5V/线序确认后仍无 UAC → 换带 UAC 的摄像头，或保留 INMP441 |
| 只有 48 kHz、降采样质量差 | 中 | 识别率掉 | 先 3 点平均；不行加 `esp-dsp` biquad 抗混叠 |
| 回声自触发 | **高** | TTS 后重复识别 | 半双工（已给 API）；AEC 放最后 |
| USB Host + WiFi + TLS 抢内存 | 中 | 重启/掉线 | PSRAM octal；UVC 缓冲走 `heap_caps_malloc(MALLOC_CAP_SPIRAM)`；TLS 只留一条长连接 |
| IR 库不可移植 | **高** | 红外功能延期 | 放 M7，且默认**不做**；产品核心不需要 |
| 搬完丢 OTA | 确定 | 升级要插线 | 认下来；要 OTA 就重排分区（2×3 MB + 6 MB，无余量） |
| 一次性大改难定位 | 中 | 回归 | 双轨 + 每里程碑打 tag `av-m1`…`av-m7` |
| `usb_stream` 补丁丢失 | 低 | 换机器编不过 | vendored 进 `components/`，不依赖外部克隆 |

**回退**：任何里程碑不过 → 板子重烧 `lamp_s3_tencent`（A 轨道），`lamp_av` 留在分支上继续改，不影响演示。

### A.3 `starved` 判读表（这次新加的诊断，后面排查继续用）
