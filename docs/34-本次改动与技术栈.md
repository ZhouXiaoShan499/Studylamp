## 2. 联网核心：`wifi_link`

### 2.1 为什么重写

旧实现只有一组 `ssid` / `pass`，`wifiTick()` 永远重试同一张网，凭据还得等人点网页才写进去。换到另一个地方（家里 ↔ 办公室）就必然掉网，且没有任何「换一张」的概念。

而语音识别本来就跑在板内（PDM 麦克风 → 腾讯云 ASR → LLM），USB 只承担「看结果」。所以真正卡住「插电即用」的不是音频，是**设备不会自己选网**。

### 2.2 NVS 数据结构

命名空间 `lampwifi`：

| 键 | 类型 | 含义 |
|---|---|---|
| `nets` | JSON 数组 | `[{"s":"ssid","p":"pass"}, ...]`，最多 5 条 |
| `last` | 字符串 | 上次成功连上的 SSID（开机快路径） |
| `ssid` / `pass` | 字符串 | **兼容键**，始终同步为最近成功的那张 |

`begin()` 会把老固件只写的 `ssid` / `pass` 迁移进 `nets`，并继续维护它们 —— 所以**回刷老固件也还能联网**。表满时替换最久没用的那张。

### 2.3 选网流程

```text
上电
 │
 ├─ 有保存的网络？
 │    ├─ 没有 → 开热点 LAMP-1-XXXX（一次性配网入口）
 │    └─ 有   → 先试「上次连上的那张」────────────── 1~3 s 通常完成
 │                 │失败
 │                 ▼
 │            扫一遍 2.4 GHz 空口（异步，不阻塞 loop）
 │                 │
 │                 ├─ 看得见的已保存网络：按 RSSI 从强到弱依次试（每张 12 s 上限）
 │                 ├─ 一张都看不见：盲试上次那张（隐藏 SSID 只能这么连）
 │                 └─ 全失败：30 s 后重来；同时热点兜底，手机可介入
 │
 └─ 连上 → 记下 SSID 作为下次快路径 → SNTP 对时 → 语音链路可用
```

### 2.4 关键常量

| 常量 | 值 | 取值理由 |
|---|---|---|
| `kMaxNetworks` | 5 | 覆盖家庭 + 办公室 + 手机热点够用，再多 NVS 和扫描匹配都变累赘 |
| `kConnectTimeoutMs` | 12 000 | 6 秒不够等慢 DHCP；密码错一般 2~3 秒就返回 `WL_CONNECT_FAILED`，会走提前失败分支 |
| `kScanTimeoutMs` | 12 000 | 与连接超时同量级，避免一张网拖住整轮 |
| `kMaxScan` | 24 | 扫描结果只留最强的一批，够用且省 RAM |
| `kRetryIntervalMs` | 30 000 | 既不至于把射频占死，换房间后也能很快恢复 |
| `kLostGraceMs` | 4 000 | 掉线先等 4 秒（路由器重启/切信道很常见），别一掉就重新扫 |

### 2.5 状态机

对外暴露 5 个相位：`idle` / `connecting` / `scanning` / `online` / `retry`。

其中 `busy()` 是关键接口 —— `net_console` 用它判断「现在开热点会不会打断一次正在进行的握手」，避免 `WiFi.mode()` 把正在进行的连接打断。

### 2.6 接口一览

```cpp
namespace wifilink {
  constexpr size_t kMaxNetworks = 5;

  void begin();                    // 读 NVS、迁移旧格式、用 secrets.h 播种；不碰射频
  void start();                    // 外设初始化完后调用，开始第一轮
  void tick(uint32_t now);         // loop() 里推进状态机

  bool hasCredentials();           // 有没有可用的凭据
  size_t savedCount();
  String savedSsid(size_t index);
  int lastIndex();                 // -1 = 没有记录

  bool connect(const String& ssid, const String& pass);  // 存并立即连
  bool connectSaved(size_t index);                       // 连表里第 index 张
  bool forget(const String& ssid);
  void clearAll();
  void autoConnectNow();           // 人为触发一轮重新挑选

  int scan(uint32_t timeoutMs = 6000);  // 同步扫描，返回可见 AP 数
  int scanCount();
  String scanSsid(int i);  int scanRssi(int i);
  int scanChannel(int i);  bool scanSecure(int i);
  int scanKnownIndex(int i);       // 命中的已保存下标，-1 = 没保存过

  bool online();  String activeSsid();  String ip();  int rssi();
  const char* phase();             // idle/connecting/scanning/online/retry
  bool busy();                     // 正在扫描或连接
  String summary();                // 给 status 命令的一行摘要
}
```

### 2.7 `main.cpp` 的接线

`setup()` 拆成两步：

1. `wifilink::begin()` —— 只读 NVS，**不碰射频**；
2. 外设初始化完之后 `wifilink::start()` —— 避开开机电流尖峰和 I2S / 射频抢资源。

`loop()` 里 `wifiTick(now)` → `wifilink::tick(now)`。

## 3. 设备端控制台：`net_console`

### 3.1 为什么两个端口

页面在 **80**，WebSocket 单独占 **81** —— `WebServer` 处理 upgrade 头很麻烦，拆成两个服务各自省事。

### 3.2 路由

| 路由 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 返回编译进固件的设备页 |
| `/api/state` | GET | 当前状态 JSON（灯、语音、网络） |
| `/api/cmd` | GET / POST | 文本命令，和串口**走同一条分发路径** |
| `/api/wifi/scan` | GET | 扫附近 2.4 GHz AP |
| `/api/wifi/networks` | GET | 已保存列表 + 在用 / 上次标记 |
| `/api/wifi/connect` | POST | 连新网或切到已保存的 |
| `/api/wifi/forget` | POST | 删一条记录 |
| `/favicon.ico` | GET | 204，省得日志刷 404 |

另外 `onNotFound` 在热点模式下把任意域名都指回控制台 —— 手机连上热点才会弹「登录网络」。

### 3.3 热点的角色变了

从「首次配网必须走它」降级为**纯兜底**：

- 没凭据时立即开；
- 有凭据但 25 秒（`kApFallbackMs`）还没连上才开；
- 开之前检查 `wifilink::busy()`，**不打断正在进行的连接**。

热点名 `LAMP-1-XXXX`，密码 `lamp12345`。

### 3.4 mDNS 与对时

`WiFi.setHostname()` 在 DHCP 之前设好，路由器里显示 `lamp1` 而不是 `esp32-xxxx`；`MDNS.begin()` 失败时 5 秒后再试（它会起 UDP 监听，每轮 loop 都调不值当）。连上后自动 SNTP 对时 —— 腾讯云 TC3 签名要求 ±5 分钟。

## 4. 网页：`web/device.html`

- **832 行，纯内联**，无框架、无构建、无 CDN —— 设备离线也要能打开，且 https 页面连不上 `ws://`（这正是设备自带页面的理由）。
- WiFi 区块从「必填表单」改成「**附近的网络 / 已保存**」两张列表：点一下就连，密码只在首次输入。
- `tools/embed_console.py` 把它压成 `firmware/include/console_html.h`，走 `PROGMEM`。
- 页面下的命令沿用同一套编码约定：`encodeURIComponent` 编码，空密码传 `-` 表示开放网络。

> **注意**：日常使用完全不需要打开这个页面。它只是「换到全新网络时的一次性入口」和「可选的遥控器」。

## 6. 技术栈

### 6.1 硬件与固件

| 层 | 选型 |
|---|---|
| MCU | ESP32-S3，YD-ESP32-S3-N16R8（16 MB QIO flash + 8 MB OPI PSRAM） |
| 框架 | Arduino framework on **PlatformIO**，`platform = espressif32@7.0.1` |
| 语言 | C++（`build_src_filter`、分区表 `default_16MB.csv`、LittleFS + NVS） |
| 网络 | `WiFi.h`（STA / AP 双模）、`WebServer`、**`links2004/WebSockets @2.4.1`**、`ESPmDNS`、`esp_sntp` |
| 存储 | `Preferences`（NVS 命名空间 `lampwifi`） |
| 序列化 | **ArduinoJson 7.x**（`JsonDocument` 写法） |
| 其他 | IRremoteESP8266 2.8.6；PDM 麦克风 → I2S 采集，85 KB 请求体走 `ps_malloc` |

**为什么钉 `espressif32@7.0.1`**：8.x 换到 Arduino 3.x，`ledc` / `WiFi` 等 API 有破坏性变更；不钉版本时 CI 缓存一失效就会拉到 8.0.0 然后编不过（2026-11-12 实际踩到）。

### 6.2 前端

原生 HTML + CSS + JS，**无框架、无构建、无 CDN**；通信是 `fetch` + WebSocket。

### 6.3 云端语音（本次未改，既有实现）

| 环境 | ASR | 语义 |
|---|---|---|
| `lamp_s3_tencent`（provider=4） | 腾讯云一句话识别，**TC3-HMAC-SHA256** 签名 | TokenHub Bearer |
| `lamp_s3_bailian`（provider=3） | `qwen3-asr-flash` | `deepseek-v4.1-flash` |
| `lamp_s3`（provider=1） | 默认 | 默认 |

腾讯云路线强依赖系统时钟（TC3 要求 ±5 分钟），所以连上 WiFi 会自动 SNTP；没网时串口 `time <epoch>` 手填。

## 8. 上手命令

烧录前先断开浏览器里占着 COM6 的 Web Serial 页面（`pio -t upload` 会报 `PermissionError(13)`）：

```bash
cd firmware
pio run -e lamp_s3_tencent -t upload
pio device monitor -b 115200
```

这块板的 `secrets.h` 里已有 `Xiaomi_037C`，NVS 为空时会用它播种，所以刷完应该**插电就直连、不用点任何网页**。

只有换到全新网络、且 NVS 里没有记录时，才需要一次性连它的热点（`LAMP-1-XXXX` / `lamp12345`），打开 `http://192.168.4.1/`，在列表里点一个网络输密码。

串口排查：

```text
wifi status        # 当前相位、SSID、IP、RSSI
wifi scan          # 扫附近 2.4 GHz，标记哪些已保存
wifi list          # 已保存的表
wifi join 2        # 连表里第 2 张
wifi forget 1      # 删掉第 1 张
wifi auto          # 重新挑一轮
wifi clear         # 清空（回落到 secrets.h）
```
