## 一、这次调整改了什么

| 维度 | 调整前（台灯方案） | 调整后（AI 学习机器人） |
|------|-------------------|------------------------|
| 产品品类 | AI 机器人交互台灯 | 桌面 AI 学习机器人交互设备 |
| 第一功能 | 照明 + 语音 + 动作 | **AI 语音交互** + 机械动作 |
| 照明模组 | 5V 单色灯环 / LED 灯板 + MOSFET 调光 | **取消**，灯环仅做状态反馈 |
| 屏幕 | 2.8″ 480×480 圆屏 / 0.96″ OLED | 1.09″ TFT（随 RIG-Arm） |
| 主控板 | 开发板 + 台灯结构 | RIG ESP32-S3 主控板（后续阶段） |
| 摄像头 | 列为「不开发」 | GC0308，阶段二做基础在场检测 |

**一句话结论**：取消照明后，产品从「AI 机器人台灯」正式转为「**AI 学习桌面机器人**」。不再为了保留「台灯」这个名字而勉强加入照明功能。

## 二、产品定位

### 2.1 定位句

> 一款面向大学生、年轻人及居家学习人群的**桌面 AI 机器人交互设备**：以 ESP32-S3 为核心，结合语音交互、云端大模型、摄像头视觉、机械舵机与屏幕显示，成为能听、能说、能看、会动的桌面学习助手。

### 2.2 三个关键词

| 关键词 | 含义 | 对应用户价值 |
|--------|------|--------------|
| 实体化 | AI 不再只是手机 / 电脑里的聊天窗口 | 桌面上有一个「在场」的助手 |
| 可回应 | 语音、表情、灯环、点头转头同时反馈 | 交互有存在感，不需要盯屏幕 |
| 学习向 | 问答、计时、提醒围绕学习节奏设计 | 减少在书本、手机、电脑之间切换 |

### 2.3 不做什么

| 不做 | 原因 |
|------|------|
| 照明 / 阅读灯 | 照明模组已取消；光学指标与台灯赛道不是本项目优势 |
| 端侧大模型 | ESP32-S3 不运行大语言模型，AI 计算放云端 |
| 复杂视觉识别 | 第一阶段只做图像采集与人员在场检测，不承诺行为识别 |
| 学习状态自动判定 | 「在桌前」不等于「在学习」，不对外宣传自动识别学习状态 |
| 全功能堆砌 | 先围绕语音、动作、屏幕/灯环、视觉四个方向做深 |

## 三、用户与需求

### 3.1 目标用户

| 用户群体 | 典型场景 | 主要需求 | 优先级 |
|----------|----------|----------|--------|
| 大学生 | 自习、写作业、备考 | 学习问答、知识解释、学习计时、任务提醒 | P0 |
| 年轻人 | 桌面办公、日常信息查询 | 桌面 AI 交互、语音查询、智能陪伴 | P1 |
| 居家学习人群 | 在家上网课、自学 | 语音操作、学习提醒、桌面辅助 | P0 |
| 居家办公人群 | 居家办公、远程会议间隙 | 快速语音问答、简单任务提醒 | P2 |

### 3.2 需求洞察

学习过程中，用户经常需要在书本、电脑、手机和其他设备之间切换。查一个知识点、设一个计时、记一条提醒，往往要拿起手机、解锁、打开应用、点好几次——**成本不在操作本身，而在打断学习节奏**。

用户需要的不是又一个 App，而是一个**放在桌面上、抬头就能说话、说完就有回应**的实体设备。

| 现状痛点 | 现有做法 | 本产品的做法 |
|----------|----------|--------------|
| 查资料要切设备 | 拿起手机搜索 | 直接开口问，语音播报答案 |
| 设计时步骤多 | 打开手机番茄钟 App | 一句话开始 / 暂停计时 |
| 提醒容易被忽略 | 手机通知淹没在消息里 | 屏幕 + 灯环 + 动作 + 语音多通道提醒 |
| 手机干扰专注 | 拿起手机就被其他消息带走 | 桌面设备只做学习相关的事 |

### 3.3 场景走查

| 时刻 | 场景 | 用户动作 | 设备响应 | 价值 |
|------|------|----------|----------|------|
| 09:00 | 开始自习 | 「开始 45 分钟专注」 | 屏幕进入计时、灯环呼吸、点头确认 | 不用掏手机 |
| 09:20 | 遇到不懂的概念 | 「什么是机会成本」 | 聆听表情 → 思考状态 → 语音解释 | 不打断阅读 |
| 09:45 | 计时结束 | 无需操作 | 语音提醒 + 灯环变色 + 转头看向用户 | 休息提醒更易感知 |
| 14:00 | 桌面有人坐下 | 无 | 摄像头检测到在场，屏幕进入待命表情 | 设备「知道」有人 |
| 21:30 | 收尾 | 「今天学了多久」 | 播报本次学习时长记录 | 轻量学习反馈 |

> 上表是设计目标，不是已实现功能。阶段三之前，只有语音闭环与台架能力可用。

### 5.3 已取消的硬件

| 硬件 | 原用途 | 取消原因 |
|------|--------|----------|
| LED 照明灯板 | 台灯主照明 | 产品不再做照明 |
| MOSFET 灯光驱动电路 | 灯板低边开关 / 调光 | 随照明取消 |
| PWM 亮度 / 色温调节模块 | 调光调色 | 随照明取消 |
| 2.8″ 480×480 圆形屏幕 | 原台灯方案的大屏 | 改用 RIG-Arm 自带 1.09″ TFT |
| M5Stack StickS3 | 早期备选主控 | 统一到 RIG ESP32-S3 主控板 |

### 5.4 硬件依赖与阶段门

| 依赖项 | 影响 | 未到位时的替代方案 |
|--------|------|--------------------|
| RIG-Arm 套件 | 舵机、TFT、板载麦、功放无法整机验证 | 继续用开发板 + INMP441 做软件与协议；驱动先写接口 |
| WS2812B 灯环 | 灯环状态联动无法验证 | 用板载 LED 或串口日志模拟状态 |
| GC0308 摄像头 | 视觉感知无法开始 | 先做图像链路的接口与数据格式设计 |
| 扬声器 | 语音播报无法验收 | 先用 PC 端 TTS 验证交互节奏 |
| 舵机独立电源 | 舵机不能稳定动作 | 不接舵机，只做动作序列的离线推演 |

> **阶段门原则**：硬件不到位时，只做**不依赖该硬件**的软件工作；不用开发板「假装」整机验收。

## 六、技术实现

### 6.1 系统架构

```text
        用户语音 / 桌面画面
                │
                ▼
┌───────────────────────────────┐
│ ESP32-S3 设备端                │

                │ HTTPS / WebSocket
                ▼
┌───────────────────────────────┐
│ 云端 AI 服务                   │
│ ASR 语音识别 · LLM 大模型 · TTS │
└───────────────┬───────────────┘
                │
                ▼
        扬声器 · 舵机 · TFT 表情 · 灯环状态
```

### 6.2 端云分工

| 环节 | 设备端（ESP32-S3） | 云端 |
|------|--------------------|------|
| 唤醒 / 拾音 | 按键触发、I2S 采集、VAD 句尾判断 | — |
| 语音识别 | 上传音频 | ASR |
| 问答 | 透传文本、维护会话 | LLM |
| 播报 | 下载 / 流式播放音频 | TTS |
| 动作 / 显示 | 舵机、TFT、灯环 | 下发语义指令 |
| 学习计时 | 本地计时、NVS 记录 | 可选同步 |

### 6.3 技术模块

| 技术模块 | 目标实现 | 现状 | 备注 |
|----------|----------|------|------|
| 主控开发 | ESP-IDF / C++ | PlatformIO + Arduino 主固件；另有 ESP-IDF 实验工程 | 迁入 RIG-Arm 时再评估是否统一到 ESP-IDF |
| 语音采集 | I2S | INMP441 已跑通 | 后续换板载麦需重配引脚与增益 |
| 语音识别 | 云端 ASR | 开发期用本地 Vosk | 阶段一切云端 |
| AI 问答 | 云端 LLM API | 开发期用本地 Ollama | 需要 API Key 与限流策略 |
| 语音播报 | 云端 TTS + MAX98357 | 未接 | 阶段一 |
| 舵机控制 | UART 总线舵机 | 现有 PWM 舵机代码 | 总线协议需重写驱动 |
| 屏幕显示 | 1.09″ TFT 驱动 | 未接 | 复用 RIG 板载屏驱动 |
| 摄像头 | GC0308 采集 + 基础检测 | 未接 | 按 DVP 并口评估，以套件接口为准 |
| 灯环控制 | WS2812B + RMT | 未接 | 只做状态色，不做照明 |
| 学习计时 | ESP Timer / FreeRTOS | 倒计时已有 | 阶段三学习化 |
| 数据保存 | NVS | 已有配置存储 | 后续可扩展文件存储 |

### 6.4 关键技术决策

| 决策 | 内容 | 理由 |
|------|------|------|
| AI 放云端 | ESP32-S3 只做采集、控制、联网 | 端侧算力与内存不足以跑大模型 |
| 按键触发优先 | 首版不做唤醒词 | 避免误唤醒与常驻监听，隐私边界清晰 |
| 灯环只做状态 | 不做照明、不做色温 | 产品定位已不含照明 |
| 屏幕做表情 | 用表情与状态替代大段文字 | 桌面设备应「扫一眼就懂」 |
| 摄像头先做在场 | 只判断「有没有人」 | 避免过度承诺学习状态识别 |
| 硬件抽象层 | 业务层不直接碰引脚与协议 | 从开发板迁到 RIG-Arm 时少改业务代码 |

## 七、开发规划（三阶段）

### 7.1 阶段总览

| 阶段 | 名称 | 目标 | 硬件 | 核心交付 | 验收标准 | 状态 |
|------|------|------|------|----------|----------|------|
| **阶段 0** | 台架验证（当前） | 在现有开发板上把语音闭环和协议跑稳 | 现有开发板 + INMP441 + 按键 + PC | 语音闭环、串口命令、状态机、HAL 边界 | 提问 → 文本回答可连续复现 | 🔄 进行中 |
| **阶段一** | 核心 MVP | 先做出能交流、能动作的机器人 | RIG-Arm（到位后） | 云端 ASR/LLM/TTS、扬声器、1–2 个总线舵机、TFT 状态 | 提问 → AI 回答 → 语音播报 → 舵机动作 | ⬜ 待硬件 |
| **阶段二** | 视觉感知与灯环联动 | 让设备具备基础视觉感知与状态联动 | + GC0308 + WS2812B 灯环 | 图像采集、在场检测、灯环状态、屏幕/灯环/舵机联动 | 画面可采集、在场检测可运行、状态能联动 | ⬜ 待硬件 |
| **阶段三** | 学习辅助与整机完善 | 从交互机器人升级为学习辅助设备 | 整机结构 | 学习问答、番茄钟、提醒、时间记录、外壳与结构 | 整机联动 + 学习功能可用 | ⬜ 待开始 |

> **阶段 0 不单独计入对外三阶段**，它是当前正在进行的台架准备。阶段一才是产品意义上的「核心 MVP」。

### 7.2 阶段 0：台架验证（当前）

| 项目 | 内容 |
|------|------|
| 目标 | 在现有硬件上把语音链路、指令协议、状态机跑稳，为迁入 RIG-Arm 做准备 |
| 硬件 | ESP32-S3-DEVKITC-1 + INMP441 + HW-483 + PC |
| 已完成 | 麦克风采集、本地 Vosk ASR、本地 Ollama 问答、按键触发、串口调试、倒计时 |
| 未完成 | 云端 ASR/LLM、TTS、连续 10 次 ≥8 次成功率、配网不重烧固件 |
| 退出条件 | 语音闭环可连续复现；协议与状态机稳定；不依赖具体硬件 |

### 7.3 阶段一：核心 MVP

**目标**：先做出能交流、能动作的机器人。

| # | 任务 | 类型 | 依赖 | 验收 |
|---|------|------|------|------|
| 1 | ESP32-S3 连接 Wi-Fi | 软件 | 无 | 上电自动联网，断线重连 |
| 2 | 麦克风采集语音 | 软件 / 硬件 | RIG-Arm 板载麦 | 16 kHz 单声道稳定采集 |
| 3 | 对接云端 ASR、LLM、TTS | 软件 | 云服务账号 | 一句话完成识别 → 回答 → 合成 |
| 4 | 扬声器播放 AI 回答 | 硬件 | MAX98357 + 扬声器 | 回答可听清，无明显爆音 |
| 5 | 1–2 个总线舵机实现点头、转头 | 软件 / 硬件 | RIG-Arm 舵机 + 独立电源 | 动作平滑、限位安全 |
| 6 | TFT 显示聆听 / 思考 / 回答状态 | 软件 / 硬件 | 1.09″ TFT | 状态与语音流程同步 |

**阶段验收**：用户提问 → AI 回答 → 语音播报 → 舵机动作，完整跑通一次。

| 风险 | 影响 | 应对 |
|------|------|------|
| RIG-Arm 未到 | 无法整机验收 | 先在开发板完成云端链路与协议，硬件到了只换驱动 |
| 云端延迟 | 交互卡顿 | 流式 ASR/TTS、首句优先播报 |
| 舵机供电不足 | 复位 / 抖动 | 独立电源、共地、软启动 |
| TTS 音色生硬 | 体验差 | 选合适音色，控制回答长度 |

### 7.4 阶段二：视觉感知与灯环联动

**目标**：让设备具备基础视觉感知能力。

| # | 任务 | 类型 | 依赖 | 验收 |
|---|------|------|------|------|
| 1 | 接入 GC0308 摄像头 | 软件 / 硬件 | 摄像头 + 接口 | 稳定出图，帧率满足检测 |
| 2 | 实现稳定图像采集 | 软件 | 阶段二硬件 | 连续采集 10 分钟不崩溃 |
| 3 | 尝试基础人员在场检测 | 软件 | 采集链路 | 有人 / 无人二分类可运行 |
| 4 | 接入 WS2812B 灯环 | 软件 / 硬件 | 48mm 灯环 | 状态色可编程 |
| 5 | 联动屏幕、灯环与舵机状态 | 软件 | 上述模块 | 同一状态三处反馈一致 |

**阶段验收**：摄像头能够采集画面，基础在场检测可运行，交互状态能够联动反馈。

| 风险 | 影响 | 应对 |
|------|------|------|
| 摄像头接口不匹配 | 无法采集 | 先确认 RIG 板引出接口与供电 |
| 光照变化误检 | 在场判断不稳 | 只做「有人/无人」，不做行为判断 |
| 灯环电流 | 挤占电源 | 限制亮度与点亮数量 |
| 隐私顾虑 | 用户不接受 | 图像本地处理、不上传、可物理遮挡 |

### 7.5 阶段三：学习辅助与整机完善

**目标**：从 AI 交互机器人升级为学习辅助设备。

| # | 任务 | 类型 | 依赖 | 验收 |
|---|------|------|------|------|
| 1 | 学习问答与知识解释 | 软件 | 阶段一语音链路 | 学习类问题回答可用 |
| 2 | 番茄钟、学习计时 | 软件 | TFT / 灯环 | 25/45 分钟计时准确 |
| 3 | 学习任务与休息提醒 | 软件 | TTS + 舵机 + 灯环 | 到点多通道提醒 |
| 4 | 基础学习时间记录 | 软件 | NVS | 可按天查询专注时长 |
| 5 | 优化外壳、舵机结构与交互 | 结构 | 3D 打印 / 结构件 | 整机可稳定摆放与演示 |

**阶段验收**：完成 AI 交互、机械反馈、视觉感知和学习辅助功能的整机联动。

## 八、范围边界与风险

### 8.1 风险登记

| 风险 | 可能性 | 影响 | 应对 |
|------|--------|------|------|
| RIG-Arm / 灯环到货延迟 | 高 | 阶段一、二推迟 | 软件先行，硬件到了只换驱动 |
| 云端服务成本 / 延迟 | 中 | 体验与成本 | 限长回答、缓存、流式播报 |
| 总线舵机协议不熟 | 中 | 动作开发慢 | 先单舵机标定，再做动作序列 |
| 摄像头误检被当成「学习状态」 | 中 | 对外承诺过度 | 只宣传在场检测 |
| 照明取消后卖点减少 | 中 | 产品差异化不足 | 用语音 + 动作 + 学习场景补足 |
| 用户不需要桌面机器人 | 中 | 项目方向不成立 | 阶段一后做真实用户验证 |
| 现有台架代码与新产品口径混淆 | 高 | 对外表达不一致 | 文档标注历史口径，网页写明阶段 |

### 8.2 对外表述边界

| 可以说 | 不可以说 |
|--------|----------|
| 桌面 AI 学习机器人 | AI 台灯 / 智能台灯 |
| 语音问答、学习计时、任务提醒 | 自动识别学习状态 |
| 摄像头基础人员在场检测 | 坐姿识别、专注度分析 |
| 概念样机 / MVP 阶段 | 量产、已通过认证 |
| 灯环用于状态反馈 | 灯环用于阅读照明 |
