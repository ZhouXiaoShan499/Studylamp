## 5. 两个必须记录的问题

### 5.1 prob 太低，容错余量薄

- `0.153`（开灯）、`0.140`（关灯）、`0.467`（关灯）
- 含义：模型认为该命令的概率只有 14%~47%，只是「矮子里拔将军」选了得分最高的那条
- **后果不是"不能用"，而是"稍微变一点就错"**：说「把灯打开」不行，说「开个灯」不行，换个人、换个距离可能匹配到别的命令

可能原因（按可能性排序，尚未验证）：

| # | 原因 | 验证方法 |
|---|---|---|
| 1 | 说话距离远 / 音量小（peak 仅 1679） | 靠近到 10~20 cm 重测，看 prob 是否上升 |
| 2 | 房间混响，AFE 降噪吃掉细节 | 换小房间 / 加软装 |
| 3 | mn7 量化模型本身 prob 分布偏低 | 无解，属模型特性 |

**下一步只需做第 1 条验证**，一个动作就能区分「环境问题」和「模型问题」。

### 5.2 `GATE_BY_WAKEUP` 名不副实 —— 但「免唤醒」的结论下得太早（2026-11-08 22:1x 更正）

`main.c` 的真实结构：

```c
#if GATE_BY_WAKEUP
if (res->wakeup_state == WAKENET_DETECTED) {
    ESP_LOGW(TAG, "*** wake word detected ***");
    gpio_set_level(PIN_LED, 1);      // 闪灯
    multinet->clean(modelData);      // 清状态
}
#endif

esp_mn_state_t mnState = multinet->detect(modelData, res->data);  // ← 确实每帧都跑
```

`#if` 只包住「打印 + 闪灯 + 清状态」。**这一段没写错**：`detect()` 确实从不跳过。

**但由此推出「所以直说也能识别」是错的。** 真正的门控不在 `#if`，而在 `multinet->create(mnName, 6000)` 的第二个参数：

| 事实 | 依据 |
|---|---|
| `create(name, duration)` 的 duration 是「多久没听到命令就进入 `ESP_MN_STATE_TIMEOUT`」 | `esp_mn_iface.h` 函数注释原文：*The duration (ms) to trigger the timeout* |
| 进入 TIMEOUT 后 `detect()` 不再返回结果，必须 `clean()` 才能重开 | 官方 `cn_speech_commands_recognition` 示例：收到 TIMEOUT 就 `enable_wakenet()` + `wakeup_flag=0`，停止调用 detect |
| 原代码只在**唤醒词**分支里调 `clean()` | `main.c:275-288` |

于是真实行为是：

```
开机 → 6 秒窗口打开 → 没人说话 → TIMEOUT（代码没处理）→ 从此 detect() 永不出结果
                                              ↑
                        只有「你好小智」能 clean() 一次，重开 6 秒窗口
```

**这才是「先说你好小智再开灯可以、直接说开灯没反应」的完整解释。** 而当日日志里 `815409` 那次「距上次唤醒 11.9 秒仍识别成功」，实际是前面还有一次唤醒词，被我当时的 grep 过滤掉了 —— 用一条被裁剪的日志下结论，是这次误判的直接原因。

**修正**：循环里补 `ESP_MN_STATE_TIMEOUT → multinet->clean()`，并把窗口放到 10 分钟。实测直说「关灯」即可生效（见 §9）。

**误触发仍然存在**：`818017` 那次 `peak=83 rms=72`（很弱的信号）就触发了识别。日常环境里电视、聊天声都可能让它动作。真正的门控要用 `afe->disable_wakenet()` / `enable_wakenet()`，不是靠一个 `#if`。

## 9. 修正：直说「开灯」没反应（2026-11-08 22:1x）

### 9.1 根因

`multinet->create(mnName, 6000)` 开的是一个 **6 秒识别窗口**。窗口过期后模型进入
`ESP_MN_STATE_TIMEOUT`，`detect()` 不再返回结果；原代码只处理 `DETECTED`，完全没处理
`TIMEOUT`，所以窗口关了就不会再开。

唯一能让它重开的是唤醒词分支里的 `multinet->clean()` —— 于是表现成：

```
「你好小智」+ 「开灯」  → 能开（clean 重开了窗口）
直接「开灯」            → 没反应（窗口早已 TIMEOUT）
```

和「唤醒词门控」的现象一模一样，但机理完全不同。`detect()` 从来没有被 `#if` 跳过。

### 9.2 改动（`main/main.c`，共 3 处）

| 位置 | 改动 | 行数 |
|---|---|---|
| 宏区 | 新增 `MN_WINDOW_MS 600000`；`GATE_BY_WAKEUP` 注释改为「只闪灯，不门控」 | +7 |
| `multinet->create` | 第二个参数 `6000` → `MN_WINDOW_MS` | 改 1 |
| 主循环 | 新增 `else if (mnState == ESP_MN_STATE_TIMEOUT) { multinet->clean(...); }` | +10 |
| 开机横幅 | 打印 `window=...ms, auto-reopen` 与「direct say」提示 | +5 |

窗口取 10 分钟的理由：窗口越短，「话说到一半被 `clean()` 截断」的概率越高；10 分钟
在实际使用中基本不会超时，同时保留 TIMEOUT 分支作为兜底。

### 9.3 实测

固件 977 KB，`app-flash` 写入 11.5 s，Hash verified。启动：

```
W (2119) lamp_sr: LAMP-SR ready (window=600000ms, auto-reopen)
```

先说 6 秒窗口版本验证过一次超时重开（每约 6.3 秒一行 `mn window expired, reopened`），
改成 10 分钟后不再出现该行（符合预期：窗口没到）。

**直说验证**（全程无 `wake word detected`）：

```
W (129963) lamp_sr: MN id=2 prob=0.302 text= guan deng
W (129964) lamp_sr: >>> voice:off level=0 LED=OFF
```

「关灯」在没有任何唤醒词的情况下被识别并执行 —— **修复生效**。
