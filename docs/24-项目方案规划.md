## 1. 项目定义

### 1.1 一句话

> 一款放在书桌上的 **桌面 AI 机器人**：抬头说一句话，它就能听懂、回答、并用屏幕表情、灯环和转头点头回应你。

### 1.2 产品形态

```text
产品形态（目标）
  头部    1.09″ TFT 表情 · GC0308 摄像头 · 麦克风 · WS2812B 状态灯环
  关节    单柱 + 1–2 个总线舵机（转头 / 点头）
  底座    ESP32-S3 · MAX98357 功放 · 扬声器 · 5V 供电
```

- **能听**：麦克风拾音 → 离线命令词 / 云端 ASR
- **能说**：云端 LLM 生成回答 → TTS → 功放播报
- **会动**：1–2 个总线舵机做转头、点头、待机微动
- **有表情**：1.09″ TFT 显示聆听 / 思考 / 回答 / 计时；灯环只做状态色
- **看得见**（阶段二）：GC0308 摄像头做「有人在 / 没人」的基础在场检测

### 1.3 用户与场景

| 用户 | 场景 | 需求 | 优先级 |
|------|------|------|--------|
| 年轻职场人（25–32 岁） | 下班后自学、考证、写东西 | 学习问答、知识解释、计时、提醒 | P0 |
| 桌搭 / 数码爱好者 | 桌面布置与展示 | 桌面 AI 交互、状态反馈、可展示的形态 | P1 |
| 居家办公 | 远程办公间隙 | 快速语音问答、提醒 | P2 |
| 送礼人群 | 生日 / 入职 / 毕业 | 有形态感、免说明书的桌面礼物 | P3 |

> **2026-11-09 起不把大学生当主力人群**：整机物料数百元、零售难低于 399，学生不是这个价位的付费者；学生更适合做传播者。

**核心价值不是「又一个 AI 音箱」，而是把 AI 从手机屏幕里拿出来，放到桌面上，用整个身体回应。**

### 1.4 明确不做

| 不做 | 原因 |
|------|------|
| 照明 / 阅读灯 | 已取消；光学指标不是本项目优势 |
| 端侧大模型 | ESP32-S3 跑不动，AI 放云端 |
| 学习状态 / 坐姿 / 专注度识别 | 「在桌前」≠「在学习」，不过度承诺 |
| 全功能堆砌 | 只围绕语音、动作、屏幕/灯环、视觉四个方向做深 |
| 量产 / 认证承诺 | 当前是概念样机与 MVP 阶段 |

## 2. 现状盘点（2026-11-09 实测口径）

### 2.1 硬件

| 部件 | 型号 / 规格 | 接口 / 引脚 | 状态 |
|------|-------------|-------------|------|
| 主控 | ESP32-S3-DEVKITC-1，N16R8（16 MB Flash / 8 MB octal PSRAM） | — | ✅ 在用 |
| 麦克风 | INMP441（I2S MEMS） | BCLK=16 / WS=18 / SD=17，**32 bit 槽宽** | ✅ 已跑通 |
| 按键 | HW-483 轻触模块（低电平有效） | GPIO4 | 🟡 代码完整，实物未通 |
| 调试负载 | HW-479（仅 G 通道） | GPIO5 | ✅ 在用（**非产品 BOM**） |
| 状态灯 | 板载 / 外接 LED | GPIO14 | ✅ 在用 |
| 供电 | USB（5V/2A 充电头待换） | — | 🟡 待脱离电脑 |
| 功放 / 屏幕 / 舵机 / 灯环 / 摄像头 | — | — | ⬜ 未到货 |

> **32 bit 槽宽是硬约束**：INMP441 是 24 bit 数据、MSB 对齐在 32 bit 槽里。用 16 bit 槽会错位输出低频漂移（`firmware/src/pdm_mic.cpp` 有注释记录）。

### 2.2 固件：两条线并行

| | A 线：`firmware/idf/lamp_sr/` | B 线：`firmware/src/`（PlatformIO） |
|---|---|---|
| 框架 | ESP-IDF 5.4.3 | Arduino-ESP32 2.0.17 |
| 语音 | esp-sr 2.6.1：AFE + WakeNet9 + MultiNet7（**离线命令词**） | WebSocket 推流 + 云端 ASR（provider 1/2/3） |
| 已有能力 | 5 条命令词、按键任务、GPIO 输出、10 分钟自动重开窗口、8 倍前置增益 | 红外学习/发送、定时任务、OLED（可选）、PWM 舵机、色温调光、事件日志、NVS |
| 代码量 | `main.c` 487 行 | `main.cpp` 777 行 + `voice_client.cpp` 514 行 + `cloud_asr.cpp` 477 行 |
| 定位 | **当前主线**：验证「板上离线听懂人话」 | **功能仓库**：一旦要红外/定时/舵机，从这里取 |
| 状态 | ✅ 已烧录运行（COM5） | ✅ 可编译（CI 全环境） |

**A 线已验证的能力边界**（`docs/20`）：

- 说「开灯」→ GPIO5 输出高；说「关灯」→ 输出低；不联网、不花钱、断电即用
- 3 次命令 3 次正确，但置信度 `prob` 只有 **0.14–0.47**（正常应 0.8+），**余量很薄**
- 唤醒词**不门控**：直说也能认，前提是识别窗口没超时（已改为 10 分钟 + 超时自动重开）
- 「亮一点 / 暗一点 / 最亮」只注册、未实测；GPIO5 是开关量，**没有真正的 PWM 调光**

> 代码里已加入 `MIC_PRE_GAIN 8`（+18 dB 前置增益）补偿远距离拾音，但**尚无对应的实测记录**——代码里有、文档里没有，应优先补测并在 `docs/23` 登记。

## 3. 关键决策（需要拍板，附建议）

### D1：还要不要那个「灯」？

| | 路线 A：语音开关灯 | 路线 B：桌面 AI 机器人 |
|---|---|---|
| 依据 | 近两周的实际需求 | `docs/11` 的产品定位 |
| 核心 | 真实光源 + MOSFET 驱动 + 多档调光 | 语音问答 + 表情 + 动作 + 视觉 |
| 还缺什么 | MOSFET 模块、灯带/灯泡（几十元） | 功放、TFT、舵机、灯环、摄像头（整套未到） |
| 现在能做 | ✅ 1 天可收尾 | 🟡 只能做不依赖硬件的软件 |
| 交付物 | 一个能用的桌面语音开关 | 一台能演示的机器人 |

**建议：不做二选一，做「先后」。**

- 路线 A 的软件部分（离线识别）**已经做完了**，只剩驱动电路，1 天能收尾 → 先做完，手上有一件真正能用的东西；
- 路线 B 被硬件卡死，`docs/11` 自己就写着「硬件不到位时只做不依赖该硬件的软件工作」；
- 但**对外口径不能混**：A 是 Demo，B 是产品。网页、README、演示话术必须区分。

**决策截止**：2026-11-12（本周内）。选 A 就买 MOSFET + 灯；选 B 就把 A 降级为「技术验证」，不加硬件。

### D2：阶段一用哪套固件底座？

| | 选项 1：`lamp_sr` 继续自研 | 选项 2：迁小智（xiaozhi-esp32） |
|---|---|---|
| 现有资产 | 离线唤醒 + 命令词已通（按键待修） | 完整 ASR+LLM+TTS、MCP 工具生态 |
| 硬件适配 | 自己写（RIG-Arm 接口未知） | 需适配板型，且要升 IDF 到 6.0 |
| 可控性 | 高，代码全是自己的 | 中，受上游节奏影响 |
| 工作量 | 加 LLM/TTS/屏幕/舵机，按模块推进 | 一次迁移，收益大但风险集中 |

**建议：阶段一选 1，阶段三再评估 2。**

理由：硬件还没到，迁移的收益无法验证；而 `lamp_sr` 的离线唤醒是**已经跑通的确定性资产**，先把它变成「能对话的机器人」，比换底座更稳。小智作为「阶段三整机化」的备选，不作为现在的任务。

### D3：云端大脑选谁？

| 方案 | 状态 | 问题 |
|------|------|------|
| 阿里云百炼 | ❌ 已停用 | 账号欠费、延迟 10–13 s、模型名一个月下架两次（`docs/13`） |
| 腾讯云 | ⬜ 只有方案 | 无单 Key，TC3 签名要在 MCU 上现算（`docs/14`） |
| DeepSeek 官方 API | 🟡 代码有端点、未验证 | `provider=2` 已支持 OpenAI 兼容端点（`api.deepseek.com` / `deepseek-flash`），但没有 build env，且语音跳仍依赖百度凭据 |
| 本地 Ollama | ✅ 可用 | 需要 PC 常开，不是产品形态 |

**建议：阶段一用「离线命令词 + DeepSeek 文本 API」的组合。**

- 固定指令（开灯、计时、音量）走**离线**：0 延迟、0 费用、断网可用；
- 开放问答走**云端 LLM**：只传文本，不传音频，成本和隐私都更好；
- ASR 先用离线命令词顶着，等有了喇叭和稳定网络再评估云端 ASR。

> **注意**：离线命令词在 A 线（`lamp_sr`），云端 LLM 在 B 线（`firmware/src` 的 `provider=2`，已配 `api.deepseek.com`）。**阶段一的第一件事就是把这两条能力合并到同一底座**（见 D2）。

### D4：阶段一的触发方式？

| 方式 | 体验 | 误触发 | 建议 |

## 4. 总体方案

### 4.1 目标架构（阶段一）

```text
① 固定指令（离线，不出网）
   用户语音 → 麦克风 → AFE → MultiNet → 状态机 → 舵机 / TFT / 灯环

② 开放问答（云端，只传文本）
   识别出的文字 → HTTPS → DeepSeek → 文本回答 ─┬→ TTS → 功放
                                                └→ 动作标签 → 状态机
```

一句话：**固定指令在板上闭环，开放问答才出网；出网只传文本。**

### 4.2 端云分工

| 环节 | 设备端 | 云端 |
|------|--------|------|
| 唤醒 / 拾音 | 按键、I2S、AFE（VAD/AEC/NS） | — |
| 固定指令 | **离线 MultiNet 识别 + 本地执行** | — |
| 开放问答 | 文本上行、会话维护 | LLM |
| 播报 | 音频下行、I2S 播放 | TTS |
| 动作 / 显示 | 舵机、TFT、灯环 | 下发语义标签（如 `nod` / `think`） |
| 计时 / 记录 | 本地计时、NVS 存储 | 可选同步 |

**原则：能本地做的绝不联网；联网只做「必须靠大模型」的那一步。**

### 4.3 固件分层（为换硬件做准备）

```text
应用层   状态机 / 命令分发 / 学习功能
   │
服务层   语音服务 · 云端客户端 · 动作序列 · 显示 · 计时
   │
抽象层   mic_iface / audio_out_iface / servo_iface / display_iface / led_iface
   │
驱动层   I2S · UART · SPI · RMT · GPIO · NVS
```

要求：**业务代码不直接碰引脚和协议**。从开发板迁到 RIG-Arm 时，只换驱动层。

### 4.4 交互状态机（阶段一）

| 当前状态 | 触发 | 下一状态 | 设备反馈 |
|----------|------|----------|----------|
| IDLE | 按键 / 唤醒词 | LISTEN | 抬头、表情「聆听」、灯环呼吸 |
| LISTEN | 识别到文本 | THINK | 表情「思考」、轻微点头 |
| LISTEN | 超时 / 无语音 | IDLE | 回到待机，屏幕淡出 |
| THINK | LLM 返回 | SPEAK | 表情「说话」、播放音频 |
| THINK | 失败 / 超时 | ERROR | 表情「困惑」+ 语音降级提示 |
| SPEAK | 播放结束 | IDLE | 回到待机 |
| ERROR | 提示播完 / 3 s | IDLE | 回到待机 |
| IDLE | 开始计时 | TIMER | 屏幕显示进度、灯环变色 |
| TIMER | 到点 / 手动停止 | IDLE | 语音 + 灯环 + 动作三通道提醒 |

每个状态对应：一个屏幕表情、一个灯环色、一个默认动作（如 LISTEN 点头、THINK 微动）。**三处反馈必须一致**——这是阶段二验收项，但状态机要在阶段一就定好。

### 4.5 协议（设备 ↔ 云端）

```jsonc
// 请求
{ "type": "ask", "text": "什么是机会成本", "session_id": "lamp-01", "ctx": [] }

// 响应
{ "type": "answer", "text": "机会成本是指……", "action": "nod", "emotion": "thinking" }

// 错误
{ "type": "error", "code": "RATE_LIMIT", "message": "..." }
```

要求：
- 只传文本，不上传原始音频（阶段一）；
- 超时 8 s 降级为「网络不太好，再说一遍好吗」；
- 动作标签是**枚举**，设备端有默认值，云端返回未知标签时忽略而不是报错。

### 4.6 安全与隐私

| 项 | 措施 |
|---|---|
| API Key | 只放 NVS 或本地 `secrets.h`（已 gitignore）；CI 扫描 `sk-*` / `AKID*` |
| 音频 | 阶段一不上传；若后续上云 ASR，明确告知并提供物理静音 |
| 摄像头 | 图像本地处理、不上传、可物理遮挡（阶段二） |
| 账号 | 不用个人主账号做长期依赖（百炼欠费已踩过一次） |
| 儿童 / 隐私 | 不做常驻录音，按键触发优先 |

## 6. 验收指标（量化，先写死）

| # | 指标 | 目标 | 测量方法 | 当前 |
|---|------|------|----------|------|
| 1 | 离线命令词识别率 | **≥8/10**（50 cm，安静房间） | 同一句说 10 次，数正确次数 | 3/3（样本不足） |

### 6.1 用户验证（阶段一之后）

技术指标达标不等于产品成立。阶段一验收后，必须做一次真实用户测试：

| 项 | 设计 |
|---|---|
| 对象 | 3–5 位目标用户（25–32 岁职场学习者），不是朋友捧场 |
| 场景 | 把设备放在他的书桌上，连续用 3 天 |
