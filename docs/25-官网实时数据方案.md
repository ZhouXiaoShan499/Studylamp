# 25 官网实时数据方案（2026-11-10）

> **2026-11-11 更新**：硬件已插上（COM6 · ESP32-S3 原生 USB），主力方案改为 **浏览器直连 USB（[`docs/28`](28-实时数据方案v2-USB直连.md)）**。本文的服务端中继**不废弃**，降级为「手机 / 远程 / 不支持 Web Serial」的第二通道，两条通道共用同一套解析与渲染。
>
> **文档性质**：设计与执行方案。回答两个问题——官网现在有什么、怎么把真实数据实时显示上去。
>
> **与 `docs/11` / `docs/24` 的关系**：定位以 `11` 为准，排期以 `24` 为准，本文只补「网站 + 实时数据」这一块，不改产品定义，不改阶段划分。
>
> **口径纪律**（本项目最容易被扣分的地方）：
> 1. 仿真不叫实测。脚本生成的数据只能标 `DEMO`，不能标 `LIVE`。
> 2. 真实数据必须能指到来源（串口、TCP、服务端进程），且页面上的来源徽标与之一致。
> 3. 没接的硬件字段显示 `—` 或「未接」，不填 0，不填假值。

## 0. 一页纸摘要

| 问题 | 答案 |
|------|------|
| 官网是什么 | `web/` 下 4 个静态页（概览 / 产品 / 数字样机 / 技术）+ 一份共享 CSS/JS，零构建、零依赖，push `main` 由 GitHub Actions 发布到 Pages。 |
| 现在有实时数据吗 | **没有。一个都没有。** 全站 0 处 `fetch` / `WebSocket` / `EventSource`；数字样机里那些「实时读数」全部由页面内 `state` 对象脚本生成，页脚自己也写着「非实测数据」。 |
| 数据能从哪来 | 三层就绪度：**T0 今天就有**（PC 服务端进程状态、问答耗时、ESP32 TCP 连接数）；**T1 加串口桥就有**（唤醒、命中命令词、麦克风 RMS、堆内存，全在现有 `ESP_LOGW/ESP_LOGI` 日志里）；**T2 固件加 WiFi 才有**（姿态、表情、计时、在场、RSSI）。 |
| 推荐方案 | **服务端状态总线 + SSE 推送 + REST 快照兜底**，新开一页 `web/live.html` 展示；数字样机 `?live=1` 放到 P2 再接。理由：静态站不引入构建链、aiohttp 已有、SSE 自带重连、单向遥测不需要 WebSocket。 |
| 第一步做多久 | **P0 约 1–1.5 人日**：新增 `server/telemetry.py`、`web/live.html`、`web/assets/live.js`，`lamp_server.py` 挂 3 条路由。**现有四页一行不改。** |
| 页面上怎么保证不说假话 | 三态徽标：`DEVICE`（绿，字段来自真机）/ `SERVER`（黄，字段来自服务端进程）/ `DEMO`（灰，录制回放，标录制时间）；断流 >10 s 变 `STALE`。 |

## 1. 网站现在有什么

### 1.1 站点结构与部署

```text
web/
├─ index.html         23 KB   概览：hero + 5 个板块 + 概念状态条
├─ product.html       28 KB   产品：hero + 6 个内容板块（结构/反馈/运动/语音/时间/边界）
├─ simulator.html    139 KB   数字样机：整机 SVG + 控制台 + 约 1.2k 行内联脚本
├─ technology.html    31 KB   技术：系统图 + 工程取舍 + 规格表 + 状态表
└─ assets/
   ├─ site.css         20 KB   设计令牌与全站外壳（header / footer / 按钮）
   ├─ pages.css        72 KB   各页组件样式（home-hero / sim-cta / spec 表…）
   ├─ site.js         4.5 KB   header 滚动、移动端菜单、滚动入场；**无任何数据请求**
   └─ *.webp / *.svg / og.jpg  产品渲染图、爆炸图、场景图
```

- 无 `package.json`、无打包器、无框架。所有页面直接 `<script src>` + 内联脚本。
- `.github/workflows/pages.yml`：`push main` 且改动落在 `web/**` 时，把 `web` 整个目录作为 Pages artifact 发布 → `https://zhouxiaoshan499.github.io/Studylamp/`。
- **推论一**：Pages 托管不了 WebSocket/SSE/REST，只能托管静态文件。
- **推论二**：Pages 是 HTTPS，页面去连 `http://192.168.x.x:8080` 会被浏览器当混合内容拦掉。这一点决定了 §3.8 的三种运行形态。

**`simulator.html` 数字样机（重点）**

| 区域 | 元素 | 现在由什么驱动 |

| 控制台 BODY | 电源开关、在场检测（有人 / 离开 / 自动）、6 个表情、双轴舵机滑杆、点头/左看/右看/归位、专注计时 15/25/45/60 | `setPresence()` `setExpression()` `setPower()` 等 |
| 控制台 VOICE | 按住说话、示例指令、文字输入、对话记录 | 本地脚本匹配关键词，**不录音、不上传、不调模型**（页面自己写明） |
| 叙事块 | 「此刻 / THE MOMENT」一句自然语言描述 | `syncNarrative()` 由 state 拼出 |
| 页脚遥测 | 功率 W / 舵机状态 / 视觉状态 | `updatePowerModel()` 等，脚本估算 |
| 页脚声明 | 「前端行为仿真 · 舵机角度与检测结果为脚本生成 · 非实测数据」 | 写死 |

内部结构（接入时要用的）：

```js
const state = { power, presence:{detected,confidence,distance,auto}, expression,
                expressionManual, yaw, tilt, selectedMinutes, timer:{active,endsAt,totalMs,minutes} };
const view  = { yaw, tilt, presence, ring, ringAlpha };   // 渲染用的插值量
const sim   = { servoBusy, lastMoveAt, autoNextAt, watts };
// 单循环：requestAnimationFrame(tick) → 舵机 78°/s 缓动 → render(now, dt)
// 已支持 URL 参数：?mode=voice / ?presence=1 / ?expr=listen / ?power=off
```

**这三个特点决定了接入方式**：单文件 3.2k 行不适合大改；`state` 已经是完整的目标模型，只要有一个「外部写入 state + 调 `syncAllControls()`」的入口就够了；已有的 URL 参数机制天生适合再加一个 `?live=1`。

### 1.3 页面之外还有一套 Web

`server/web/index.html`（7.9 KB）是 `lamp_server.py` 自带的聊天页：`ws://<host>:8080/ws`，文字提问 + 按住麦克风上传 16 kHz PCM，服务端跑 Vosk → Ollama，逐 token 回推。**它已经有真实的双向 WebSocket，但只服务聊天，没有任何状态可视化，也不属于官网**。方案里复用它背后的服务进程，不复用这个页面。

### 1.4 结论

| 页面元素 | 现在看起来像 | 实际来源 | 接真实数据时的处理 |
|----------|--------------|----------|--------------------|
| 舞台态度、yaw/tilt | 实时遥测 | `state` 脚本 | T2 才有；之前显示「未接」 |
| 在场检测置信度 / 距离 | 实时遥测 | 随机数 + 自动切换定时器 | T2 才有；之前显示「未接」 |
| 功率 1.1 W | 实测 | `sim.watts` 估算 | 永远标「估算」，不接 |
| 语音对话记录 | 真识别 | 关键词脚本 | 接真机时可换真链路，但仍是 DEMO |
| 技术页状态表 | 工程状态 | 人工维护 | P0 即可接服务端心跳，变成真状态 |

## 2. 实时数据能从哪里来

### 2.1 今天真实存在的数据源

| 源 | 通道 | 已有字段 | 频率 | 限制 |
|----|------|----------|------|------|
| `server/lamp_server.py` | HTTP 8080 / WS `/ws` / TCP 8766 | ASR 是否就绪、模型名、每次问答的首 token 延迟与总耗时、当前连着的 ESP32 数量、连接/断开事件、错误 | 事件驱动 | 进程内状态，需自己聚合成「状态总线」 |
| `server/voice_server.py` | WS 8765 | 同上（旧链路，Arduino 固件时代） | 事件驱动 | 与 `lamp_server.py` 二选一在跑，别同时接 |
| 固件 `firmware/idf/lamp_sr/main/main.c` | **仅串口日志**（487 行，esp-sr 离线命令词，**这一版固件没有 WiFi**） | `*** wake word detected`、`MN id=… prob=… text=…`、`>>> 开灯 level=1 LED=ON`、`mic peak=… rms=…`、`vad=speech dbfs=…`、`afe …` 启动参数 | 事件 + 诊断行 | 需要 PC 串口桥；没有网络 |
| 历史固件（docs/06、07、09 记录） | WiFi + WebSocket → 8765 | 语音帧、识别结果 | — | 代码已不在当前 `firmware/` 树里，回收成本高，**不推荐为了遥测回去复活它** |
| `docs/` | 人工记录 | 实测结论 | — | 不能自动更新 |

### 2.2 三层就绪度

```text
T0  服务端进程           今天可用   问答耗时 / ASR 就绪 / 连接数 / 错误      → 立刻可上站
T1  串口日志（不动固件）  0.5 人日   唤醒 / 命令词命中 / RMS / 堆内存        → 事件流可上站
T2  固件 + WiFi          依赖硬件    姿态 / 表情 / 计时 / 在场 / RSSI / 温度  → 姿态镜像可上站
T3  公网 + 历史          可选       趋势图 / 回放 / 分享链接                  → 展示用
```

> **关键判断**：不必等硬件。T0 + T1 已经能撑起一个「看起来确实是真机」的监测台——因为「22:14:03 唤醒 → 22:14:04 命中『开灯』prob 0.87 → 22:14:04 GPIO5 拉高」这条时间线，比一个假的 yaw 角有说服力得多。

### 2.3 哪些字段值得上站

| 候选字段 | 展示价值 | 频率需求 | 采集成本 | 结论 |
|----------|----------|----------|----------|------|
| 语音阶段（听到 / 思考 / 回答）+ 耗时 | 高（最能说明「它在工作」） | 事件 + 1 Hz | T0 低 | **P0** |
| 命令词命中（文本 + prob） | 高 | 事件 | T1 低 | **P0** |
| 在场检测（有人 / 无人 + 置信度） | 高 | 1 Hz | T2 | P1 |
| 姿态 yaw / tilt | 中（样机已能表现） | 5 Hz 够，1 Hz 也行 | T2 | P1 |
| 计时剩余 | 中 | 事件 + 1 Hz | T1/T2 | P1 |
| RSSI / 堆 / 温度 / 运行时长 | 中（证明这是真机） | 0.2 Hz | T2 | P1 |
| 麦克风 RMS / VAD 电平 | 中（当电平条很带感） | 5 Hz | T1 | P2 |
| 功率 W | 低 | — | 需电流采样 | **不上**，继续标估算 |
| 对话全文 | 低 + 有隐私风险 | 事件 | T0 | **默认不上**，只传字数 |
| 原始音频 / 摄像头画面 | 高但**不做** | — | 高 | **明确不做**（隐私 + 带宽） |
| 传感器高频波形（>5 Hz） | 低 | — | — | **不做**，没有信息量 |

## 3. 方案

### 3.1 三条链路对比

| 维度 | A. 设备直连浏览器 | **B. 服务端中继（推荐）** | C. 云 MQTT over WSS |
|------|------------------|--------------------------|---------------------|
| 拓扑 | 浏览器 → `ws://lamp.local:81` | 设备/串口 → PC 服务 → 浏览器 | 设备 → 云 broker → 浏览器 |
| 今天能不能做 | 不能（固件无 WiFi） | **能，且立刻有 T0 数据** | 不能（固件无 WiFi） |
| 公网可用 | 否 | 反代后可 | 是 |
| 成本 | 0 | 0（复用 PC） | 账号 + 流量 |
| 延迟 | 最低 | 低（局域网 <50 ms） | 中（100–300 ms） |
| 安全面 | 设备暴露在局域网 | 只有服务端暴露，可加 token / 白名单 | 需只读 ACL + 密钥管理 |
| 典型坑 | 混合内容、mDNS、设备并发连接数 | 服务端得常开 | 密钥写进前端 = 等于公开 |
| 结论 | 只做本机调试 | **P0–P2 主链路** | P3 公网演示再评估 |

### 3.2 推荐架构

```text
┌─────────────┐   TCP 8766（STATE 行）   ┌──────────────────────────────────────┐
│ ESP32-S3    │ ───────────────────────► │  lamp_server.py (aiohttp :8080)      │
│ 固件 T2     │   或串口 /dev/ttyUSB0     │  ┌────────────────────────────────┐  │
└─────────────┘ ───────────────────────► │  │ TelemetryHub                   │  │
                                          │  │  · last_state + seq + ts       │  │
┌─────────────┐   POST /api/v1/ingest     │  │  · events 环形缓冲（200 条）    │  │
│ 串口桥 T1   │ ───────────────────────► │  │  · subscribers（asyncio.Queue） │  │
│ tools/…     │                          │  └────────────────────────────────┘  │
└─────────────┘                          │   GET /api/v1/state     快照          │
                                          │   GET /api/v1/events    SSE 推送       │
                                          │   POST /api/v1/commands P2 控制        │
                                          └───────────────┬──────────────────────┘
                                                          │ SSE（同源或 CORS）
                                                          ▼
                                          ┌──────────────────────────────────────┐
                                          │ web/live.html + assets/live.js        │
                                          │  DEVICE / SERVER / DEMO / STALE 徽标  │
                                          └──────────────────────────────────────┘
                    GitHub Pages 只托管上面的静态文件（DEMO 时回放录音 JSON）
```

### 3.3 为什么是 SSE

| 选择 | 理由 |
|------|------|
| **SSE 而不是 WebSocket** | 遥测是单向的；SSE 是普通 HTTP，自动重连（`retry:`）、断点友好、aiohttp 里 30 行写完、不需要在前端引库。WebSocket 留给 P2 的双向控制（而控制可以直接用 `POST`，仍然不需要 WS）。 |
| **不在页面里直连设备** | 混合内容、局域网发现、设备并发都难；而且设备今天根本没联网。 |
| **P0 不上 MQTT** | 密钥会进前端公开文件；固件也没联网能力。等真需要公网再说。 |
| **不引入图表库** | 全站零依赖是现状，不能为了一个 sparkline 破坏它。60 秒趋势用 `<canvas>` 或纯 SVG 折线，40 行够。 |
| **不引前端框架** | 同上。`live.js` 用原生 ES2020，`<script type="module">` 都不需要。 |

### 3.4 数据契约 v1

**状态快照**（`state` 对象；字段可缺，缺 = 未接）

```json
{
  "v": 1,
  "seq": 10231,
  "ts": 1762786419123,
  "source": "device",
  "device": { "id": "lamp-01", "fw": "0.4.1", "hw": "REV-C-bench", "uptime_s": 4210 },
  "link":   { "transport": "tcp", "rtt_ms": 18 },
  "power":  { "on": true },
  "presence": { "detected": true, "confidence": 0.93, "distance_m": 0.62, "auto": true },
  "expression": "aware",
  "pose":   { "yaw": 26.0, "tilt": 36.0, "moving": false },
  "timer":  { "active": true, "remaining_ms": 1213000, "total_ms": 1500000 },
  "voice":  { "state": "speak", "heard_len": 7, "reply_len": 23, "last_ms": 1840 },
  "health": { "heap_kb": 122, "temp_c": 41.2, "wifi_rssi": -57 }
}
```

| 字段 | 类型 | 单位 | 来源层 | 缺失时前端显示 |
|------|------|------|--------|----------------|
| `source` | enum `device/server/demo` | — | 服务端判定 | `UNKNOWN` 灰标 |
| `expression` | enum `idle/aware/listen/think/speak/timer` | — | T2 | 「未接」 |
| `pose.yaw` / `pose.tilt` | number | 度 | T2 | `—` |
| `presence.*` | bool / 0–1 / m | — | T2 | `—` |
| `timer.remaining_ms` | int | ms | T1/T2 | `--:--` |
| `voice.state` | enum `idle/listen/think/speak` | — | T0 | `—` |
| `voice.last_ms` | int | ms | T0 | `—` |
| `health.*` | number | KB / ℃ / dBm | T2 | `—` |
| `link.rtt_ms` | int | ms | 服务端测得 | `—` |

**事件**（`type: "event"`，进事件流）

```json
{ "v":1, "type":"event", "seq":10232, "ts":1762786419456,
  "kind":"command", "level":"info",
  "text":"命中『开灯』prob 0.87 · GPIO5 → 高" }
```

`kind` 取值：`boot` `link_up` `link_down` `presence_in` `presence_out` `wake` `command` `asr` `reply` `timer_start` `timer_end` `servo_move` `error`。

**兼容规则**：读方忽略未知字段、未知 enum 降级为「未知」；`v` 主版本变化才改结构；`seq` 单调递增用于丢帧检测；时间一律用服务端 `ts`（ESP32 无 RTC 电池，设备时钟不可信）。

### 3.5 采样、刷新与时钟

| 层 | 频率 | 说明 |
|----|------|------|
| 设备 → 服务端 | 1 Hz 快照 + 变化立即发 + 5 s 心跳 | 只在状态变化时增加报文，静止时几乎零流量 |
| 服务端 → 浏览器 | 1 Hz + 事件即推 + 15 s SSE 心跳注释 | 心跳防代理掐线 |
| 浏览器 → DOM | 文本 ≤ 4 Hz，数字用 `tabular-nums` | 避免 60 fps 重排 |
| 浏览器 → 画面 | 单 `requestAnimationFrame` 插值（样机已有 `approach()`，78°/s） | 数据来的是 1 Hz，视觉是连续的 |
| 保留期 | 内存 60 s 环形 + 200 条事件；P3 落 SQLite，1 分钟降采样存 30 天 | — |

**时钟**：客户端不信任设备时间。收到 `ts` 后记录 `offset = ts - Date.now()` 并做滑动平均；倒计时由 `remaining_ms` 换算成 `endsAt = performance.now() + remaining_ms`，本地平滑递减，每次收到新快照纠偏。

### 3.7 三态徽标与视觉纪律

| 徽标 | 含义 | 触发条件 |
|------|------|----------|
| `DEVICE`（绿） | 至少一个字段来自真机 | 收到 `source:"device"` |
| `SERVER`（黄） | 只有服务端进程数据 | `source:"server"`，设备字段全 null |
| `DEMO`（灰） | 录制回放 | 无后端，加载 `assets/demo-telemetry.json` |
| `STALE`（红） | 曾经连上、现在断了 | 最后一条消息 > 10 s |

- 徽标旁边永远写出「采样 1 Hz · 未接字段显示「未接」」，把不确定性写在脸上。
- 数字用等宽 + `font-variant-numeric: tabular-nums`，避免跳动。
- 尊重 `prefers-reduced-motion`：呼吸环和粒子动画全部停用。
- `aria-live` 只放在连接状态和事件流上；姿态数字不加，否则读屏会被刷屏。
- **首页与产品页不出现实时数据**，避免把 DEMO 当实测。技术页 `#status` 状态下限可以接 P0 心跳（「ASR 就绪 · 今日 12 次问答」）。

### 3.8 Pages 托管下的三种运行形态

| 形态 | 页面从哪来 | 数据从哪来 | 用途 |
|------|------------|------------|------|
| **本地演示**（推荐日常） | `lamp_server.py` 直接托管 `web/`（新增 1 条静态路由） | 同源 `/api/v1/*`，无 CORS | 开发、验收、给硬件同事看 |
| **内网访问** | Pages 或本机 | 服务端开 CORS 白名单 `https://zhouxiaoshan499.github.io` | 手机/平板看；HTTPS 页面连 HTTP 会被拦，**必须用 http 打开页面**或走反代 |
| **公网演示** | Pages | Caddy / Cloudflare Tunnel 把 8080 反代成 `https://…` + SSE 关缓冲 | 对外演示；只读，控制接口关闭 |

### 5.1 `server/telemetry.py`（核心 60 行）

```python
import asyncio, json, time
from aiohttp import web

def sse_frame(name: str, payload: dict) -> bytes:
    body = json.dumps(payload, ensure_ascii=False, separators=(",", ":"))
    return f"event: {name}\ndata: {body}\n\n".encode()

class Hub:
    def __init__(self):
        self.state = None
        self.seq = 0
        self.events: list[dict] = []
        self.subs: set[asyncio.Queue] = set()
        self.started = time.time()

    def _stamp(self, obj):
        self.seq += 1
        return {**obj, "v": 1, "seq": self.seq, "ts": int(time.time() * 1000)}

    def publish_state(self, state: dict):
        self.state = self._stamp({**state, "type": "state"})
        self._fanout("state", self.state)

    def publish_event(self, event: dict):
        ev = self._stamp({**event, "type": "event"})
        self.events.append(ev)
        del self.events[:-200]
        self._fanout("event", ev)

    def _fanout(self, name, payload):
        for q in list(self.subs):
            try:
                q.put_nowait((name, payload))
            except asyncio.QueueFull:
                self.subs.discard(q)      # 慢客户端直接踢掉，不让它拖垮别人

    async def stream(self, request: web.Request) -> web.StreamResponse:
        resp = web.StreamResponse(headers={
            "Content-Type": "text/event-stream; charset=utf-8",
            "Cache-Control": "no-store",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",
        })
        await resp.prepare(request)
        q: asyncio.Queue = asyncio.Queue(maxsize=64)
        self.subs.add(q)
        try:
            await resp.write(b"retry: 3000\n\n")
            if self.state:
                await resp.write(sse_frame("state", self.state))
            while True:
                try:
                    name, payload = await asyncio.wait_for(q.get(), timeout=15)
                except asyncio.TimeoutError:
                    await resp.write(b": ping\n\n")   # 心跳注释，防代理掐线
                    continue
                await resp.write(sse_frame(name, payload))
        except (ConnectionResetError, asyncio.CancelledError):
            pass
        finally:
            self.subs.discard(q)
        return resp
```

### 5.2 挂到 `lamp_server.py`

from telemetry import Hub

hub = Hub()
app["state"]["hub"] = hub

async def api_state(request):
    return web.json_response(hub.state or {"v": 1, "type": "state", "source": "none"})

async def api_ingest(request):
    if request.headers.get("X-Lamp-Token") != os.environ.get("LAMP_INGEST_TOKEN", ""):
        raise web.HTTPForbidden()
    body = await request.json()
    for ev in body.get("events", []):
        hub.publish_event(ev)
    if body.get("state"):
        hub.publish_state(body["state"])
    return web.json_response({"ok": True, "seq": hub.seq})

app.router.add_get("/api/v1/state", api_state)
app.router.add_get("/api/v1/events", hub.stream)
app.router.add_post("/api/v1/ingest", api_ingest)

const API = new URLSearchParams(location.search).get('api') || '/api/v1';
const BADGE = document.getElementById('liveBadge');
const ring = [];                       // 60 s 趋势
let lastAt = 0, clockOffset = 0, pollTimer = 0, es = null;

function link(source, text) {
  BADGE.dataset.source = source;       // device | server | demo | stale
  BADGE.textContent = text;
}

function apply(s) {
  lastAt = Date.now();
  clockOffset = s.ts - lastAt;
  document.getElementById('liveSeq').textContent = '#' + s.seq;
  document.getElementById('liveUpdated').textContent = new Date(s.ts).toLocaleTimeString('zh-CN', { hour12: false });

  // 每个字段单独判空：缺 = 显示「未接」，不要用 0 冒充
  setOrDash('poseYaw',   s.pose?.yaw,   v => Math.round(v) + '°');
  setOrDash('poseTilt',  s.pose?.tilt,  v => Math.round(v) + '°');
  setOrDash('cardPresence', s.presence?.detected, v => (v ? '有人' : '无人'));
  /* … 其余字段同理 … */

  drawPose(s.pose); drawTrend(ring.push({ t: lastAt, rtt: s.link?.rtt_ms }));
  if (s.source) link(s.source, { device: 'DEVICE', server: 'SERVER', demo: 'DEMO' }[s.source] || 'UNKNOWN');
}

function setOrDash(id, value, fmt) {
  const el = document.getElementById(id);
  el.textContent = (value === undefined || value === null) ? '未接' : fmt(value);
  el.classList.toggle('is-unset', value === undefined || value === null);
}

function connect() {
  es = new EventSource(`${API}/events`);
  es.addEventListener('state', e => apply(JSON.parse(e.data)));
  es.addEventListener('event', e => pushEvent(JSON.parse(e.data)));
  es.onerror = () => {
    // EventSource 会自己重连；这里只负责界面提示与轮询兜底
    if (Date.now() - lastAt > 6000) startPolling();
  };
}

function startPolling() {              // 代理掐掉长连接时的降级
  if (pollTimer) return;
  pollTimer = setInterval(async () => {
    try { apply(await (await fetch(`${API}/state`, { cache: 'no-store' })).json()); }
    catch { link('stale', 'STALE'); }
  }, 1000);
}

// 10 s 没有新数据 → STALE；不是「最后一次值还在，就当它还在」
setInterval(() => { if (lastAt && Date.now() - lastAt > 10000) link('stale', 'STALE'); }, 1000);

## 7. 风险与对策

| 风险 | 后果 | 对策 |
|------|------|------|
| Pages 是 HTTPS，连不上 HTTP 服务 | 上线后一片空白 | §3.8 三形态写清；`DEMO` 兜底；内网必须用 http 打开 |

| 固件迟迟没 WiFi | 姿态/在场永远「未接」 | T0/T1 已经够撑场；字段显示「未接」比假数据可信 |
| SSE 被代理/运营商掐 | 数据停更但看着像实时 | 15 s 心跳 + `retry` + 1 s 轮询兜底 + `STALE` |
| 改样机弄坏现有演示 | 首页 CTA 挂掉 | P2 才动，且只加 1 个 export + 1 个 script 标签；PR 前录屏对比 |

| 长连接 + 全局 rAF 一起跑 | 笔记本发热 | `visibilitychange` 暂停、DOM 4 Hz、sub 上限 3 |
| 一人多开标签页 | 服务端连接数堆高 | 每 IP SSE 上限 + 慢消费者踢除 |
