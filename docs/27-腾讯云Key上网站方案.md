# 27 腾讯云 Key 上网站方案（2026-11-11）

> 回答一个问题：腾讯云调用能不能「跟进到网站上」？
> **能，但 Key 绝不能进前端。** 前端只发音频、只收文本；签名和密钥留在本机代理里。
>
> 前置：`docs/14`（腾讯云两跳方案、TC3 细节、错误码表）、`docs/26`（设备端直连方案）、`docs/25`/`docs/28`（网站与实时数据）。

---

## 0. 结论

| 问题 | 答案 |
|------|------|
| 浏览器能直接调腾讯云 ASR 吗 | **不能**：ASR 要 SecretKey 现算 TC3 签名；把 SecretKey 写进 `web/` 等于公开密钥（Pages 是公开产物，任何人 F12 就能抄走） |
| 那网站怎么用 | 加一层 **本机代理**（aiohttp，仓库里 `server/lamp_server.py` 已经在跑）：浏览器 → 代理 → 腾讯云 |
| 改动量 | 代理 60~100 行 + 页面一个卡片，约 **1 人日** |
| 能不能先只跑通调用 | 能，而且**不用动网站**：`tools/tencent_voice_check.py` 已经写好，填 Key 就能跑 |

---

## 1. 三种「上网站」的边界

| 方案 | Key 放哪 | 延迟 | 谁能用 | 结论 |
|------|----------|------|--------|------|
| A 浏览器直连腾讯云 | 前端 JS（必然可见） | 最低 | 任何人抄走 Key 烧你额度 | **不做** |
| **B 本机代理（推荐）** | PC 环境变量 / `.secrets/` | 一次内网往返 | 你本机、同局域网 | **现在做这个** |
| C 云函数 URL（SCF） | SCF 环境变量 | 冷启动 +100~300 ms | 可给公网，但要有短 token | 量产再做 |

> 有一个例外不要误解：腾讯云「临时密钥 STS」也不是纯前端方案——签发 STS 仍然需要一个能加签的服务端。绕不开代理。

## 2. 代理契约

```text
POST /api/v1/asr
     body: application/octet-stream（完整 WAV，16k/单声道/16bit）
     回:   {"text":"开灯","ms":420,"requestId":"..."}   或 {"error":{"code":"...","message":"..."}}

POST /api/v1/intent
     body: {"text":"开灯"}
     回:   {"label":"on","ms":380}

GET  /api/v1/health
     回:   {"asr":"ready|missing-key","llm":"ready|missing-key","model":"..."}
```

实现要点：

1. **复用 `tools/tencent_voice_check.py` 里的 `build_authorization()`**——不要在服务端再写一套签名，两套实现必然漂移。
2. 只监听 `127.0.0.1`；要跨域时白名单放 `https://zhouxiaoshan499.github.io` 和 `http://localhost:*`。
3. 限流：每 IP 每分钟 20 次、单请求音频 ≤ 3 MB（base64 后，腾讯云上限）。
4. **不落盘音频、不打印 Base64、日志只记「字节数 + 文本长度 + 耗时」**。
5. 代理自己不做「回答」，只做「识别」与「打标签」，把大模型输出限制在 16 token，防跑飞。

## 3. 页面怎么放

在 [`web/live.html`](../web/live.html) 现有布局里加一张卡，与 Web Serial 面板并列：

```text
┌ 语音 → 文本 ─────────────────────────────┐
│ [按住说话]  ── 16k PCM ──> WAV ──> 代理  │
│ 识别：开灯 · 420 ms · 腾讯云一句话识别      │
│ 意图：on（可选，第二跳）                   │
└──────────────────────────────────────────┘
```

- 录音用 WebAudio 采 16 kHz 单声道，前端自己拼 44 字节 WAV 头（和固件 `writeWavHeader()` 同一套字段）。
- 结果走同一个 `ingest()` 风格的入口，直接进页面右侧「事件流」，和真机串口事件混排——这样一页能同时看到「设备在干什么」和「云端听成了什么」。
- 页脚必须写清：**音频只发往本机代理，再由代理发给腾讯云；浏览器里没有任何密钥。**

## 4. 安全红线（写成检查项，PR 时逐条过）

1. `grep -rn "AKID\|sk-" web/` 必须为 **0 命中**；更省事的办法是跑 `python tools/scan_cloud_keys.py --web-only`（命中即退出 1）。
2. Key 只出现在 `.secrets/`（已 gitignore）或环境变量里；`firmware/include/secrets.h` 同样已忽略。全仓体检用 `python tools/scan_cloud_keys.py`：退出码 1 = 有被 git 跟踪的 Key（会泄露），2 = 只在本地未跟踪文件里。
3. 用**子账号密钥**，只授 `QcloudASRFullAccess`；控制台开日限额 + 用量告警。
4. 代理默认 `127.0.0.1`；公网暴露（Tunnel / 反代）前必须加 token + 来源白名单 + 限流。
5. 公开演示页（GitHub Pages）**不接真实代理**：没有代理时页面显示「未连接」并回放录制，别让访客以为能直接用。

## 5. 分阶段

| 阶段 | 做什么 | 验收 | 预计 |
|------|--------|------|------|
| **P0 打通调用** | 填 Key，跑 `tools/tencent_voice_check.py --asr-only` | 输出「开灯」，耗时记下来 | 10 分钟 |
| P1 代理 | `server/tencent_asr.py` + 3 条路由，复用签名函数 | `curl` 传 `kaitest.wav` 拿到文本 | 半天 |
| P2 页面 | `live.html` 加语音卡 | 按住说话 → 文本进事件流 | 半天 |
| P3 真机（可选） | ESP32 采音 → TCP 8766 → 代理 → 文本回传 | 说一句话，页面出现「设备听到 → 云端识别」两条事件 | 1~2 天 |
| P4 公网（可选） | Tunnel + token + 限流 | 手机能打开且 Key 不泄露 | 半天 |

## 6. 验收（代理上线前）

| 指标 | 目标 |
|------|------|
| 单次识别耗时 | ≤ 1.5 s（1.3 s 音频，局域网） |
| 错误可读性 | 失败时页面显示腾讯云 `Error.Code`，不是「请求失败」 |
| 密钥泄漏面 | `web/` 0 命中；DevTools Network 里只有代理域名 |
| 限额 | 连续 21 次请求，第 21 次返回 429 |
| 隐私 | 代理日志里没有音频内容，只有字节数与文本长度 |
