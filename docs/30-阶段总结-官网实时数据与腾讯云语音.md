### 1.4 阶段四：搬到板子上（11-12 上午）

板子烧 `lamp_s3_tencent`（provider=4），修了 5 个只有真机才暴露的问题：

| # | 现象 | 根因与修法 |
|---|------|-----------|
| 1 | 一条日志都看不到 | Arduino 的 `Serial` 默认走 UART0；加 `ARDUINO_USB_MODE=1` + `ARDUINO_USB_CDC_ON_BOOT=1` 映射到 USB |
| 2 | `[asr] oom: body 87051 B` | 未启用 PSRAM；加 `memory_type=qio_opi` + `-DBOARD_HAS_PSRAM`（实测 8.0 MB 可用） |
| 3 | 麦克风恒有直流偏置、ASR 永远「静音」 | `slot_mask=LEFT` 让 WS 周期缩成 32 BCLK；改回默认 BOTH |
| 4 | 模型回 `none` 反而把灯打开 | `"none".indexOf("on")`；先排除 none 再匹配 |
| 5 | 真人说话没反应 | 阈值 450 偏高；改 180 + 自适应 ×1.5 + 底噪封顶 220 + 连续 3 帧 + 800 ms 冷却 |

## 3. 关键决策与理由

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据怎么到网页 | **Web Serial 直连**，不是服务端 SSE | 零服务端、零 CORS、HTTPS 可用、延迟 ~2 ms；SSE 留作手机/远程备用 |
| Key 放哪 | 只在本机 `secrets.h` / `.secrets/` | 站点是公开产物，前端出现 Key 等于公开 |
| 设备直连还是 PC 中转 | **设备直连腾讯云** | 不依赖常开电脑；PC 仅用于验证与对照 |
| 意图怎么判 | **固定命令本地词表 + 其余走 LLM** | 固定命令 0 模型调用、端到端从 ~5 s 降到 ~3 s；LLM 只处理开放对话 |
| 平台版本 | 钉 `espressif32@7.0.1` | 8.0.0（Arduino 3.x）有破坏性 API 变更，CI 缓存失效后会拉到它导致编译失败 |
| CI 无 `secrets.h` | 给桩分支补空实现 | 凭据不入库，但代码必须能在无凭据时编译通过 |

## 4. 实测数据

### 4.1 PC 侧（腾讯云）

| 环节 | 结果 | 耗时 |
|------|------|------|
| ASR | `开灯。` / `关灯。` / 长句全对 | 常见 200–400 ms，偶发 1.5–2 s |
| LLM（5 条命令，思考关闭） | on/off/up/down/max 全对 | 中位 1609 ms（1203–1765） |
| TTS | 9 字 → 2.07 s / 16 kHz WAV | 656 ms |

### 4.2 设备侧

| 场景 | 日志 | 结果 |
|------|------|------|
| 说「开灯」 | `[ASR] "开灯"` → `[LLM] "开灯" -> on` → `[cmd] intent="on" -> on=1` | 通过 |
| 说「关灯」 | `[ASR] "关灯"` → `[LLM] "关灯" -> off` → `[cmd] intent="off" -> on=0` | 通过 |
| 混合路由 | `[CMD] "开灯" -> on (local)` / `[REPLY] …` | 通过 |

### 4.3 端到端

| 路径 | 耗时 |
|------|------|
| 固定命令（本地） | 录音 2 s + ASR ~1 s ≈ **3 s** |
| 闲聊（LLM） | + LLM 1.5–2 s ≈ **4–5 s** |

## 7. 安全与口径

1. 三把腾讯云 Key 只存在于 `firmware/include/secrets.h`（gitignored）；git 历史与 `web/` 扫描均 **0 命中**。
2. CI 内置 Key 扫描；本地可随时跑 `python tools/scan_cloud_keys.py --web-only`。
3. 排查模型 Key 归属时，把它发往腾讯三个官方入口；**若该 Key 属于其他平台，建议去原平台轮换**。
4. 本阶段所有「能/不能」都以串口日志、HTTP 响应或截图为证；没有实测的地方标「未实测」，不写承诺值。
