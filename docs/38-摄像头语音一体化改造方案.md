# 38 摄像头 + 语音一体化改造方案（允许改代码）

> **文档性质**：目标方案。**本次只写文档，不改代码**；文中的代码改动是后续实施项。
>
> **两阶段总览**：见 [39 第一阶段与第二阶段实施计划](39-第一阶段与第二阶段实施计划.md)；本文是第二阶段的技术细化。
>
> **方案定位**：本文是“让灯自己用 CAM12 的摄像头 / 咪头 / 喇叭”的目标方案；代码改动列在后续实施项里，本次不动代码。
>
> **适用硬件**：ESP32-S3 N16R8 + CAM12（UVC + UAC）+ HW-483 + HW-479；INMP441 最终移除。

---

## 0. 结论

| 问题 | 结论 |
|---|---|
| 能不能让灯自己用 CAM12 的咪头/喇叭 | **能**，但必须让 ESP32-S3 当 **USB Host**，跑 **UVC + UAC** |
| 现在的固件行不行 | **不行**：`lamp_s3` 是 USB 设备；`lamp_sr` 没有 USB Host |
| 要不要改代码 | **要**；这是固件工程，不是接线 |
| 推荐底座 | **ESP-IDF 5.4.3 + `usb_stream`**（UVC + UAC） |
| 分辨率 | 480×320@15fps（等时）/ 800×480@15fps（批量），**MJPEG**；12MP 用不上 |
| 最大风险 | **回声/AEC**（咪头和喇叭在同一模块上）；UVC 兼容性；USB FS 带宽；5V VBUS |
| 建议第一步 | **P0 spike**：用 `usb_camera_mic_spk` 示例验证 CAM12 能枚举、出图、出声 |

> 一句话：**要单机，就把 ESP32-S3 变成 USB Host；要快，就用第二块板或电脑当 Host。** 12MP 的 CAM12 在 ESP32-S3 上只能跑低分辨率 MJPEG。

---

## 1. 为什么必须改代码

| 事实 | 后果 |
|---|---|
| CAM12 是 USB **设备**（UVC 摄像头 + UAC 麦克风/喇叭） | 需要一个 USB **主机**来枚举它 |
| 灯板上的 ESP32-S3 当前是 USB **设备**（USB-Serial-JTAG / CDC，COM6/日志/Web Serial 都走 GPIO19/20） | 两个设备不能通信；GPIO19/20 上的摄像头不会被识别 |
| UVC/UAC 是 USB class | 需要 USB Host 栈 + class driver（`usb_host` + `usb_stream`） |
| 当前 `lamp_s3`（Arduino）没有 USB Host；`lamp_sr`（IDF）也没有 | 必须新增固件工程/组件 |

**所以：接线只能把摄像头接到 USB 口；“能不能用”完全取决于固件。** 不想改灯固件，就只能让电脑或第二块板当 Host（备选 B/C）。

---

## 2. 目标架构

```text
CAM12（UVC 摄像头 + UAC 麦克风 + UAC 喇叭）
        │ USB 2.0 FS：5V / GND / D− / D+
        ▼
ESP32-S3（USB Host）
  ├─ UVC MJPEG → 帧队列 → HTTP MJPEG 流 / 在场检测
  ├─ UAC mic  → 16 kHz PCM → VAD → ASR → LLM → TTS → UAC speaker
  ├─ Button GPIO4 / RGB GPIO5
  ├─ WiFi 控制台（HTTP + WebSocket）
  └─ NVS：WiFi / Key / 配置
```

---

## 3. 硬件接线

| 设备 | 接到 | 备注 |
|---|---|---|
| CAM12 4 根线 | USB-A 母座 / USB-C OTG → 板载 **USB** 口 | 红 5V、绿 GND、黄 D−、黑 D+；先万用表确认 |
| 板子供电 / 日志 | **COM 口**（UART Type-C）5V/2A | 不要再把电脑插到 USB 口；USB 口让给摄像头 |
| CAM12 咪头 / 喇叭 | 模块 MIC / SPK 白座 | UAC 音频 |
| INMP441 | **移除** | 3V3 只给按键 / RGB |
| HW-483 | +轨 / −轨 / GPIO4 | 不动 |
| HW-479 | −轨 / GPIO5 | R/B 悬空 |

### 3.1 三个硬件注意点

1. **VBUS**：板载 USB 口不一定对外输出 5V。先量 USB 口的 VBUS 对 GND；没有 5V 就从 **5V 排针**飞线给摄像头，或者用**有源 USB Hub**。摄像头的 D−/D+ 仍然接 USB 口。
2. **不要让电脑和摄像头同时占 USB 口**：Host 模式下 USB 口只能接摄像头；烧录/日志走 COM 口（UART，115200）。
3. **供电余量**：摄像头约 190mA（5V 侧），WiFi 峰值 ~350mA；用 5V/2A，摄像头电源脚加 100–470µF + 100nF。

> 有些板子背面有 **USB-OTG 焊点/跳线**，不短接时 USB 口只能当设备。YD-ESP32-S3 当前能枚举 COM6，说明数据线已通；Host 模式主要差 VBUS 和固件，但上电前仍建议对照板子原理图确认一次。

## 4. 固件改造

### 4.1 底座选择

| 方案 | 评价 |
|---|---|
| **新建 `firmware/idf/lamp_av`（推荐）** | 从 `lamp_sr` 复制按键/灯光/NVS 骨架，从 `usb_stream` 示例取 UVC/UAC，从 `cloud_asr.cpp` 移植云逻辑；不影响现有 `lamp_sr` |
| 扩展 `firmware/idf/lamp_sr` | 可行，但会把“离线命令词”和“USB Host/云语音”耦合在一起，回滚成本高 |
| 在 Arduino `lamp_s3` 里塞 `usb_stream` | **不推荐**：`usb_stream` 是 IDF 组件，Arduino 2.0.17 没有对应库；搬运成本高于重建 |

### 4.2 组件

| 组件 | 作用 |
|---|---|
| `usb_host`（IDF 内置） | USB Host 栈 |
| `espressif/usb_stream` | UVC + UAC：1 路摄像头 + 1 路麦克风 + 1 路喇叭 |
| `esp_http_server` / `esp_websocket_server` | 网页、事件推送 |
| `esp_wifi` | 联网 |
| `esp_http_client` + mbedtls | 腾讯 ASR / LLM / TTS |
| `esp-sr`（可选） | 离线唤醒/命令词 |
| `nvs_flash` | WiFi/Key 配置 |

### 4.3 工作项（后续代码改动，本次不做）

1. USB Host 初始化、VBUS 控制、设备枚举、描述符打印。
2. UVC：打开 MJPEG 流，协商 480×320 / 800×480，帧回调。
3. UAC mic：16 kHz 单声道，环形缓冲，VAD。
4. UAC speaker：TTS PCM 播放，音量控制，半双工。
5. ASR：PCM 封 WAV → HTTPS → 解析 → 超时/重试。
6. LLM：本地词表优先，云端兜底；JSON 解析。
7. TTS：文本 → WAV → 去掉 44 字节头 → UAC speaker。
8. 应用：按键、RGB、灯状态、WiFi 控制台、网页（摄像头流 + ASR/LLM 文本）。
9. 稳定性：WiFi 重连、看门狗、PSRAM 监控、UART 日志。

### 4.4 代码改动清单（预估）

| 文件/工程 | 改动 |
|---|---|
| `firmware/idf/lamp_av/`（新建） | 新 IDF 工程：USB Host / UVC / UAC / WiFi / HTTP / 应用 |
| `firmware/idf/lamp_sr/main/main.c` | 复制按键、灯光、NVS 骨架；不改原工程 |
| `firmware/src/cloud_asr.cpp` | 腾讯 ASR/LLM 逻辑移植到 `esp_http_client` |
| `firmware/src/tc3_sign.cpp` | TC3 签名移植（或用 mbedtls 重写） |
| `firmware/src/voice_client.cpp` | VAD/状态机参考；输入从 I2S 改成 UAC |
| `firmware/src/net_console.cpp` | HTTP/WS 参考；改成 `esp_http_server` |
| `web/device.html` | 加摄像头 MJPEG 流、TTS 开关（可选） |

### 4.5 回声/AEC（最大工程风险）

- 摄像头咪头和喇叭在**同一个模块**上；TTS 一播放，咪头就会听到。
- **P1 先做半双工**：按键触发录音；TTS 播放时静音麦克风；播完再开。
- **P2 再做 AEC**：esp-sr AFE 的 AEC 需要参考通道；可以把 TTS 的 PCM 作为参考喂给 AFE，或做软件 AEC。
- 验收：TTS 播放后 5 秒内不出现第二次 `[ASR]`。

## 5. 分阶段计划

### P0 spike（1–2 天，先做这个）

**只验证硬件，不动灯的主固件。**

- 在**独立构建**里跑 `usb_camera_mic_spk` 示例（ESP-IDF 5.4.3）。
- 接 CAM12，查：
  1. 枚举：VID/PID、UVC/UAC 描述符；
  2. UVC：MJPEG 帧，480×320 / 800×480；
  3. UAC mic：PCM RMS；
  4. UAC speaker：测试音。
- **通过标准**：四项全过。任何一项不过，先停，改走备选 B/C（第二块板/电脑当 Host）。
- 常见失败：摄像头只支持 High-Speed、只支持高分辨率、只支持等时传输；板载 USB 口没有 VBUS。

### P1 音频闭环（2–3 天）

- UAC mic → VAD → ASR → 本地意图/LLM → TTS → UAC speaker。
- 按键触发；半双工。
- 验收：说“开灯” → 灯亮；问一句 → 喇叭回答；3/3。

### P2 视频 / 网页（2–3 天）

- MJPEG HTTP 流；网页显示摄像头 + ASR/LLM 文本；WiFi 控制台。
- 验收：浏览器看到流；连续 10 分钟不崩。

### P3 整合 / 稳定（2–3 天）

- 按键/RGB/NVS/重连；2h/8h；回声调优；功耗。
- 验收：语音 8/10；2h 稳定；不接电脑。

**总投入**：约 40–60 小时；按 16h/周，约 **3–4 周**。

## 6. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| CAM12 UVC 不兼容（12MP/HS-only/只支持高分辨率） | 出不了图 | P0 spike 先验；换 2MP Full-Speed MJPEG 摄像头 |
| USB FS 带宽 | 分辨率/帧率低 | 480×320 / 800×480；MJPEG；限帧 |
| UVC + UAC 并发 | 不稳定 | `usb_stream` 1 UVC + 1 mic + 1 speaker；限流 |
| 回声/AEC | 自触发 | P1 半双工；P2 AEC |
| 板载 USB 口不输出 5V | 摄像头不亮 | 5V 排针/有源 Hub；量 VBUS |
| 云端 Key/费用/延迟 | 不可用 | 离线命令优先；Key 配置；超时降级 |
| IDF 移植工作量大 | 延期 | 先 spike；复用 `lamp_sr` / `lamp_voice` / `cloud_asr` |
| 12MP 浪费 | 成本/体积 | 产品换 2MP 或 DVP 摄像头 |

## 7. 备选方案

| 方案 | 做法 | 适合 |
|---|---|---|
| **B. 第二块 ESP32-S3 当 A/V 协处理器** | 第二块板跑 ESP-Claw / `usb_stream`，接 CAM12 的 UVC/UAC；通过 UART/WiFi 与灯通信 | 不想动灯固件；能接受两块板 |
| **C. 电脑/树莓派当 Host** | 摄像头/咪头/喇叭都接电脑；电脑跑 ASR/LLM/TTS；灯收 `/api/cmd` | 最快演示；不是单机 |
| **D. DVP 摄像头 + 带摄像头接口的板子** | GC0308/OV3660，项目原阶段二；不用 USB Host | 做产品；换硬件 + 固件 |

---

## 8. 建议

1. **要做“单机灯自己看/听/说”**：选 A（IDF USB Host + UVC/UAC），先做 P0 spike；通过再投 P1–P3。
2. **要最快演示**：选 C（电脑当 Host）。
3. **要不动灯固件**：选 B（第二块板）。
4. **要做产品**：评估 D（DVP 摄像头），12MP USB 摄像头更适合当开发件。
5. **在 UAC 麦克风验证通过之前，不要拔 INMP441**；否则灯的语音直接没了（`lamp_sr` 还会连按键一起停）。

---

## 9. 失败回退

如果 P0 spike 失败（摄像头不兼容 / 带宽不够 / 回声不可控），不要硬上：

1. **保留 INMP441**，摄像头接电脑（电脑当 Host），先做过渡验证；
2. 或换**第二块 ESP32-S3** 当 A/V 协处理器（备选 B）；
3. 或换 **2MP Full-Speed MJPEG 摄像头** 再试。
